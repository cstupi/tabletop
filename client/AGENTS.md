# client

The Godot 4.7 / C# game client and the only project with a Godot dependency. A renderer plus a geometry engine over the server's wire protocol; it has no offline mode and holds no rules.

## Layout

- `Tabletop.csproj`: `Godot.NET.Sdk/4.7.2`, `net10.0`, references `Tabletop.Geometry`, `Tabletop.Content`, `Tabletop.Protocol` only.
- `Tabletop.sln`: the client and the three libs, the solution Godot builds and exports (`<assembly_name>.sln` beside `project.godot`). `export_presets.cfg`: `Windows` (x86_64), `Linux` (x86_64), `macOS` (universal, ad-hoc signed); `scripts/release-client` runs them. A release build sets `TabletopVersion` and `TabletopWebUrl` (environment or `-p:`), which the csproj writes as assembly metadata.
- `src/Main.cs`: root node. Builds `Session`, `AssetCache`, `ClientSettings`, `SessionStore`; runs the shader warm-up when its stamp changed, then routes by `SessionPhase` to a scene.
- `src/PerfProbe.cs`: a development build's frame recorder (performance spec → The Godot client): `TABLETOP_PERF_OUT` (a CSV row per frame), `TABLETOP_PERF_GAME` (enter a game at start; `TABLETOP_PERF_REPLAY=1` its replay), `TABLETOP_PERF_SECONDS`, `TABLETOP_PERF_BENCH` (the graphics bench); `<csv>.mark` and `<csv>.shot` for a driving script; each row also carries the frame number and Godot's pipeline-compilation counters. A release build never reads them.
- `src/Core/`: Godot-free logic.
  - `Session`: the one object that outlives screens: login, `ManagementClient`, the socket, `EventApplier`, draft, presence; `Session.Replay.cs` the replay.
  - `ReplayTimeline` (`ReplayUnit`, `Stops`), `ReplayClock`: a replay's position in the log and its playback.
  - `ManagementClient`: the one HTTP client over management's `/v1`; `ManagementDtos`. `ClientHttp`: `Main`'s one `HttpClient`, decoding Brotli, gzip and deflate.
  - `IGameSocket`/`ClientGameSocket`: the socket seam and its `ClientWebSocket` implementation, offering permessage-deflate (`SocketCompression`; `Connect` and `Reauth` sent uncompressed).
  - `IDispatcher`: posts to the main thread; `ImmediateDispatcher` in tests, `GodotDispatcher` in `src/Screens/` (over `DispatchQueue`: in order, within `FrameBudget`'s 12 ms a frame, the rest the next frame).
  - Loading (spec `2026-10-25-loading-design.md`): `LoadingView` (`LoadingLine`, `EntryState`: the curtain's "Connecting…", "Reconnecting…", "Loading game…"; the strip's reconnect and "Loading models 3 of 12"; "Preparing graphics…"), `AssetProgress` (a table's files, once per wave), `LoadingGate` (a wait shows after 200 ms), `GraphicsWarmup` (the warm-up's stamp, Quality order and bar), `WarmupGlb` (a GLB per kind of glTF material).
  - `AskViewModel`: `LegalSet` to `AskMode`, and the first open Ask for my team.
  - `RenderScheduler` (`Session.Frame`, `RenderCause`): one render per dispatcher turn. `CombatLogCache` (`Session.CombatLog`, a `CombatLogState`): the combat log built once per log state.
  - `AnimationQueue`, `MoveRuler`, `HoldLevel` (the held pieces' level, stepped by PageDown/PageUp), `ContactCheck` (the Ask's terms over `Contacts.Of` in `Tabletop.Geometry`; each landing rested nearest its Z; a landing's contacts: on a base, a path through a model, within the Ask's `Separation`), `Violations` (the models in breach and why), `CommitHold` (a refused commit's ghosts), `TapeMeasure` (`MeasureReading`: the free ruler, 2D or 3D), `MoveRegions` (safe across threads: `OutlinesAsync` builds the areas on the pool; `Reaches`, the drag's landing test), `DeployView`, `GhostStash`, `GhostLooks` (what a placement ghost draws: the slot's body and mesh at its placement and facing), `GameRowActions`, `SelectionView`, `PendingDrops`, `PresenceTable`, `MenuModel` (`GrantChoices`: the menu's Add a grant over `Session.Grantable`, fetched with the rule texts from `GET /v1/properties/{hash}/grants`), `LogText`, `Names`.
  - The play screen's models: `HeaderView`, `EnemyStrip`, `UnitSheet`, `UnitCardContent` (what the card draws, equal by value: the card rebuilds only on a change and keeps its scroll; `Groups` of like models by `SheetModel.Kind`, `ModelGroup.Next` for a row's click, the unit's wound total), `SheetFocus`, `CombatLog` (`RollEntry`, `ActivationBlock`, `LogEntry`, `LineEntry`), `DecisionView`, `TargetAssignment`, `CasualtyPick`, `UndoPlan`, `HoverView`, `SightSummary`, `ShotLines`, `Formation`, `Hotkeys` (`HotKey`, `Intent`; B toggles the Show hitboxes setting for models, Shift+B Show terrain hitboxes for terrain, via `HitboxLook`), `RuleTexts`, `SpellText` (a spell's hover text: name, casting value, catalog text; on the pick-spell options and a cast block's log row), `MarkerLocks`, `CameraFocus`, `RosterView` (`RosterView.Changed`: the rows a render rebuilds), `UnitMarkers` (`FloatingResults`; `MarkerDeclutter`: which rows draw when they would overlap), `Bookkeeping` (the conditions only the unit card shows), `SoundCues` (`Cue`, `CueAt`: the cues a live batch plays with their delays and the shot's variant, read from the records `CombatLog` reads), `ModelMarks`, `TerrainLabel`, `TerrainCardContent` (the selected terrain piece's card: name, source, facing 0–359°, scale, height, each volume's kind, footprint, heights, declarations and notes; editable in setup; equal by value) and `MarkerCardContent` (a selected setup marker), `RangeRings` (the printed ranges over `RangeOutline.Of` in `Tabletop.Geometry`; `RangeRingCache`: recomputed only when the unit or its models' slots or placements change), `SightKey` (`SightCache` per assigned target, `SightSlot` for the hovered unit: a sight query is re-sent only when the pair, a model placement or the terrain changed, else the answer stands), `TurnBanners`, `RollOffBanners` (the roll-off result spec's "Team k goes first" and each team's roll, 4 s, from the ranking step's `place_k` and `rolled_<ordinal>_<k>`; `TurnBanner` queues it ahead of the batch's turn banners, not in a replay), `GameOverView`.
  - The outbound messages: `AskAnswers` (`Answer`, `Resolve`, `ChosenByClick`, `Spent`, `Move`, `Embark`, `FacingOf` with its `ExitSite`: a disembark's facing is `Containment.ExitYaw` at the drop, judged against the volumes the Ask names Impassable), `PiecePick`, `DeployView.Place`, `HandMoves` (`Drop`, `HeldDrop`, `Call`), `Menus` (`MenuContext`), `MenuModel`, `CombatLog.UndoHere`, `GameOverView.Answer`, `LobbyEdits`, `SetupEdits`, `LobbyView`, `WaitingView`.
  - `UiTheme` (palette, fonts, `PanelShape`, `DiceStyle`, icons as data; `Rgba`), `UiThemes` (`Fantasy`, `SciFi`, `Resolve`), `HudLayout` (the Hud's slots per `HudPart`, 8 px margin, `Overlays` exempt; the button row as tall as the buttons; no dice slot while the log is open; `Loading`, the strip, at the foot's centre in the button row), `CornerLine` (the corner's clipped game name and its unclipped tail).
  - `Feedback`: the player's words for a `Refused` (null for a watcher's refused presence or ping), a socket close by code, a `Rejected`, and a failed management request (`401`, `403`, `404`, `413`, `422`, `429`, `5xx`, unreachable, timed out). `LobbyView` (the seat line, team buttons, the Players list whose rows the creator places on a team with `PickTeam(teamId, participantId)`, what a non-creator waits for), `SetupWords` (texture and deployment-style names as words), `SetupLimits` and `TextLimits` (the servers' caps: 64 terrain, 32 markers, 12–144" edges, 64-character names and labels, 500-character notes, the default `Player-xxxx` name).
  - `RulesOptions`: the lobby's optional-rules controls over `Session.Options` (`Welcome.Options`): an option's value with its default, the preset a map matches (else *Custom*), the map to send (defaults dropped). `LobbyPanel` draws a preset button and one button per option, `Label (Page)`.
  - `BoardDiff` (a table layer's added, removed, reshaped and kept ids against what its nodes last drew), `AssetCache` (content-addressed; downloads capped by kind, 64 MB mesh, 16 MB texture, by Content-Length and by bytes streamed), `GlbPreflight` (and `ImageHeader`), `HeightNormals` (a print's normal map from its height), `SurfaceFamilies` (a built-in surface's family by material name), `CoalescedRefresh`, `BuiltinCatalog` (parses and checks the packed, published and served catalog), `BuiltinContent` (the catalog in use, `Changed`), `BuiltinSync` (the server's catalog by release version), `LayoutChoices` (the Load layout list, the predefined tables first; `WithTerrain` for the Random table's `ReplaceDraft`), `ClientSettings`, `GraphicsSettings` (a Quality and a Render scale override to a `GraphicsProfile`: MSAA, shadow splits, atlas and distance, scale, SSAO, soft shadows, mesh LOD threshold; `FirstQuality` by `GpuKind`; clamps loaded values; `Place` keeps a saved window rect only while a screen shows it), `SessionStore`, `UserData` (where settings, session and cache live per build), `BuildInfo` (the release version, `dev` without one, and the web origin, from the assembly metadata; `IsRelease` when it carries a web origin; window title `Tabletop 1.2.0` or `Tabletop (dev)`, login footer `Version 1.2.0` or `Development build` in warning colour, update screen).
- `src/Screens/`: `LoginScreen`, `HomeScreen`, `GameScreen` (+ `GameScreen.Play.cs`; the loading curtain until the first table stands, then the strip), `SettingsDialog`, `UpdateRequiredScreen`, `GodotDispatcher`, `FrameBudget` (the main thread's 12 ms of deferrable work a frame: the dispatcher's queue and mesh scenes).
- `src/Theme/` (namespace `Tabletop.Client.Theming`): `ThemeBuilder` (`UiTheme` to a Godot `Theme`), `Ui` (the current theme, colours and icons as Godot types, `Changed`; `Variation` type-variation names), `DiceFaces`. `Main` applies the theme to the tree root and each screen, since `Main` is a `Node`.

- `src/Panels/`: `LobbyPanel`, `PieceMenu`, `SetupToolbar`, `TeamPanel`, `WaitingPanel`, `Guarded`.

- `content/sounds/`: `shoot-1`..`shoot-3`, `impact`, `miss`, `melee`, `whiff`, `block`, `wound`, `cast-friendly`, `cast-enemy`, `fizzle`, `move` `.wav` (16-bit mono, from `scripts/sounds`; spec `2026-10-24-sound-effects-design.md`), imported as `AudioStreamWAV` (PCM, `compress/mode=0`); `export_filter="all_resources"` ships them.
- `content/themes/<id>/`: per theme `fonts/`, `icons/` and `LICENSES.md`; `fantasy` also has `panel.svg`, `button.svg` and `dice/`.
- `scenes/`: `Main.tscn` is the root that swaps `Login`, `Home`, `Game`, `UpdateRequired`; `TableView.tscn` is the table.
- `content/builtin/`: `tables/` (the four predefined 72×48 tables, `<planet>.json`, written by management's tests; management embeds them, the client only reads them over `GET /v1/layouts/builtin`), `catalog.json` (the built-in catalog: meshes, textures, 38 terrain entries with volume and mesh; embedded as `BuiltinContent.Packed`, published by `scripts/release-client builtin`), `textures/` (seven board prints from `scripts/table-textures`: grass, desert, urban, snow, ash, wasteland, alien; 1024², 12" a repeat, height in alpha, imported lossless with no alpha-border fix) and `terrain/` (33 `.glb` meshes from `scripts/terrain-meshes`, one per kind of terrain, shared only by the same terrain at other sizes, round for a circle footprint; vertex-coloured PBR, translucent materials in a node of their own). A missing file draws the piece's volumes. `MeshLoader` reads the meshes raw, so each `.glb.import` is Keep File (`importer="keep"`): an export ships an imported file only as its import. A new mesh needs the same (`BuiltinContentTests`); `scripts/release-client export` fails when a pack lacks a mesh or a texture's import (`scripts/pck-files` lists a pack).

## How it works

- `Main` swaps one screen at a time on `Session.PhaseChanged`: `LoggedOut` to Login, `LoggedIn` to Home, `UpdateRequired` to UpdateRequired, anything else to Game.
- `UpdateRequiredScreen` names `ClientSettings.DownloadUrl` (`WebUrl` + `/download`) and opens it. `ClientSettings.Default` is `DefaultFor(BuildInfo.Current)`: a release build reaches management at its web origin and the socket at `wss://<host>/ws`; a development build the local stack. A release build ignores persisted server addresses and never writes them (`ClientSettings.Load`/`Save` take the `BuildInfo`).
- Management: `ManagementClient` sends the version header on every request and the bearer once `Jwt` is set. `Session` refreshes the JWT every 60 s from `Main`; a failed refresh backs off one minute.
- Game socket: `ClientGameSocket` raises `FrameReceived`/`Closed` on its own thread. `Session` posts them through `IDispatcher` and ignores frames from a socket that is no longer current.
- `Session.Handle` takes `Welcome`, then the board, then events. Events go into an `EventApplier`; `Session.Projection` is its `Projection`, or the `ProjectTo(seq)` prefix while an undo preview is pending.
- A `ProjectionDesyncException` triggers one resync per log position (`_desyncFloor`). A lost socket reconnects with backoff 1, 2, 5, 10 s unless the user closed it.
- `Session.CatchingUp` is true from a reset or a received board until a `ModelFacts` frame or an empty events page; floating results, turn banners and camera follow stay silent while it holds.
- `Session.EventsApplied`, `GameChanged`, `BoardChanged`, `FactsChanged`, `RefusedReceived` are what panels subscribe to. Session outlives panels: every subscription comes off in `_ExitTree`.
- Renders are coalesced: each of those four changes also marks `Session.Frame` with a `RenderCause`, and `Frame.Render(causes)` fires once per dispatcher turn (one deferred call on Godot), so a frame's batches give one render. A part that redraws from the current state subscribes to `Frame.Render` and filters on its causes (`HeaderBar`, `Roster`, `UnitCard`, `DecisionBox`, `DiceTray`, `UndoButton`, `CombatLogPanel`, `EndMessage`, `UnitMarkerNodes`, `ModelMarkNodes`, `HoverLabels`, `RangeRingNode`, `TargetLines`, `SightLines`, `GameScreen.RefreshAll`). A part that reads the batch keeps `EventsApplied` (`FloatingText`, `SoundPlayer`, `TurnBanner`, the decision box's sealed reveal, queued in `SealedReveals` until a render shows it, `Animator`, the camera follow, `TableView`).
- Graphics: `GraphicsApplier` sets the window (borderless Fullscreen or the saved windowed rect, `Main` saving it each second it changed and on close; first start 1280×720 from `project.godot`), VSync and the directional shadow atlas from `Main`, and the table's `SubViewport` (`Msaa3D`, FSR 1 `Scaling3DScale` below 100 %, `MeshLodThreshold`), environment (SSAO) and key light (splits, max distance, angular size for soft shadows) from `TableView`, on `SettingsChanged`. The Hud is in the root viewport at full resolution. With no Quality saved, `Main` picks `GraphicsSettings.FirstQuality` for the GPU (`GraphicsApplier.Gpu`) and saves it.
- Sound: `SoundPlayer` (built beside `FloatingText` in `GameScreen.Play`) feeds each `EventsApplied` batch to `SoundCues.OnBatch`, silent while `Session.CatchingUp` or `Replaying` or when the batch holds an `Undone` (which reseeds the wound totals and open frames and drops cues still waiting). Shoot (three variants by the shooting frame's id): an `attack-sequence` starting under an open `shooting` frame, once per frame; Impact or Miss: a `hit` roll under `shooting` with or without a success; Melee or Whiff: the same under `melee`; Block: a `defense` roll with every die blocked; Wound: a `defense` roll letting a wound through, a `WoundsSet` whose total rose, or a model leaving the table for the shelf; Fizzle: a failed `casting` roll; CastFriendly or CastEnemy: a casting frame's `targets` answer naming a piece of the caster's team (`Names.TeamOfUnit`) or another; Move: a `ModelsMoved` landing a model on the table (step, hand move, deployment). A batch plays each cue at most once, in order, each after the one before by `SoundCues.Gap` (0.4–0.5 s, the dice tray's tumble), so a shot reads fire, hit or miss, block or wound. Eight pooled `AudioStreamPlayer` voices play them (an idle one, else the oldest). `Settings.Sound` (default on) and `Volume` (0-100, default 70) gate and scale it.
- Feedback: every refusal toasts `Feedback.Refusal`, every close `Feedback.Closed`; `Session.LastCloseReason` is player text and Home prints it. A `1008` (the socket's JWT expired) refreshes the JWT before the reconnect. `Session.IsWatching` (a replay, an admin watcher, or from `playing` on an account with no team, except while deployment waits for players) stops presence and pings, drags, the piece, team and roster menus and Undo, and the header says the player watches. `Session.RenameAsync` patches `/v1/account`. Dialogs that take text (`PieceMenu.AskText`, `AskInteger`, Home's name fields) focus their field, confirm on Enter and stop at the servers' lengths; Leave the game asks first; in lobby and setup the lobby panel's Leave game button opens the same question. Home's End game and Delete game (`GameRowActions`, `ManagementClient.EndGame`/`DeleteGame`) are the creator's, asked first.
- Commands: `SendCommandAsync(command, id)` takes the caller's message id so a `Refused` arriving before the send's continuation can still be matched. `SendEditAsync` is for setup edits. While `Reconnecting` both queue (`Session.Queueing`, at most 16) and go out after the next `Welcome`, or fail when the session goes home. A welcomed socket gets `Reauth` with each refreshed JWT. The decision box keeps a move's or deploy's ghosts across a reconnect (`GhostStash`) for the same Ask or unit.
- Table redraw: `TableView.Redraw` runs on `BoardChanged`, `GameChanged` and each `EventsApplied` batch, and diffs each layer through `BoardDiff`. Every node (`IDrawn<T>`) keeps the item it was built from: a removed id's node leaves the tree at once, a new id gets a node, a reshaped one (terrain mesh or volumes; marker kind, diameter, label, visual or control colour; zone shape, table size or colour) is replaced, and a kept one only takes its transform, which also snaps back a refused drag. A held id (`IsHeld`) is left alone.
- Animation: `Animator` feeds `EventsApplied` into `AnimationQueue`. The projection is already current; the queue only paces playback. `Settings.Animate` false plays everything at once, true one event per call: every model the event moves (`AnimationQueue.Relocations`) glides at once, and the next event waits for the last. `Animator.Played` raises each event as it plays. The table has already redrawn the batch, so the `Animator` redraws only after a glide ends or when it consumed the player's own drop holds; `FloatingText` subscribes to `EventsApplied` before the `Animator` is made, so it reads each batch first.
- Teams (game-flow spec → One account, several teams): `Session.MyTeamIds` is every team the account holds (`Seats.Teams`: the rows sharing the account of Welcome's row), and `MyTeamId` the team acted for now (`Seats.Acting`: the team of the first open Ask waiting on one of mine, else the active team if mine, between turns (a round boundary's Ambusher picks too) the latest of mine to start a turn or answer an Ask in the live log, else my first; the decision box places a deploy pick made by any team of mine), so the decision box, unit card, roster, Tab cycle and range rings follow it. Holding several, the decision box and the game-over modal say "Playing as Team N" (`Seats.PlayingAs`), answers name their team (`AnswerAsk.TeamId`), and the camera goes to the acting team's side when it changes (`CameraFocus.TeamSide`). The lobby's team buttons join or leave each team (`TeamChoice.Edit`: `PickTeam`, `LeaveTeam`; a team another account holds reads "ask the creator to add you") and `LobbyView.Armies` gives "Your army", one picker per team held; team cards and the Players list name each member's army (`Participant.ArmyName`).
- Team games (rulebook p.50; owner ruling: "Either player from the team can take the activation across any unit in their team."): every Ask to my team is mine, with every unit of the team; `DeployView.MidDeploy` gives the team's deploy pick to every player of the team.
- Waiting for players: `Session.WaitingTeams` (`WaitingForPlayers` over the board and an empty log). While it holds the side panel stays up with `WaitingPanel` (`WaitingView`: a line per team, Join on a team no one holds, a dropdown of my armies on a team of mine with none, as in the lobby: picking one sends `PickArmy`), the header reads "Deployment waits: …" and the decision box the same lines. `GameScreen` keeps the panel and calls `WaitingPanel.Refresh` on each game info and board, which rebuilds its rows only when the lines change (`WaitingView.Changed`), so an open dropdown survives unrelated updates and a picked army clears its line once the board holds it; `GameScreen` rebuilds when a board ends the wait.
- Ask: `AskViewModel.Mine` picks the lowest-id open Ask addressed to `MyTeamId` that the team has not answered; a watcher (no team) gets none. `ModeOf(LegalSet)` maps `Options`, `PieceSelection`, `Allocation`, `Assignment`, `MoveRegion`, `TokenSpend`, `Confirmation` to `AskMode`. `DecisionBox`, in the right column above the undo and log buttons, over `DecisionView` (its controls scroll; `DecisionBox.Place`), renders the mode (hovering an option's button lights its pieces in `Palette.Hovered` and darkens the rest of the Ask's glow, so same-named units tell apart, and when the option names one unit (`DecisionView.UnitNamed`) hovers it through `TableInput.HoverUnit`: its hover label over it and, for an enemy, the enemy strip, until the pointer leaves the button; an option's `AskOption.Note` once, in warning colour, under its unit's options; `UnitCard` shows the same note through `DecisionView.NoteOf`) and answers with `SendCommandAsync(AskAnswers.Answer(ask, answer, team), id)`. A `Refused` for its last command shows as an orange refusal line and re-renders.
- The play log is `CombatLog` over `Session.Log` in `CombatLogPanel` inside `LogDrawer`; the panel renders only while the drawer is open (`CombatLogPanel.Shown`), and a render for new events keeps the rows of the leading top-level entries that draw the same (`CombatLogRows.Kept`) and rebuilds from the first that differs. `Session.CombatLog` builds it once per log state (log, count, last seq, `PendingUndoTo`, game, projection instance) and hands the same `CombatLogState` to the panel (`Entries`), the dice tray (`Latest`) and the undo button (`Undo`). The tray's 0.4 s tumble changes its faces in place (`DiceFaces.SetRaw`).
- Log lines (combat-log spec → The log; `CombatLog`, `CombatLog.Words`): an action header `R2 · Team 1 · unit · Charge → target · moved 7.5"` (`Hold → shoots target`; targets from nested frames of the same actor and the action frame's own `SelectedPieces` answers; `moved` sums each model's moves) with its lines beneath (open until clicked); a cast inside it is a nested block `Cast Hex → target` (`ActivationBlock.Nested`); one `RollEntry` per `RollRecord`, `Title` (`RollWords.Label` and `RollWords.Target`: printed value, an unapplied cover verdict, each basis change and modifier with its `Via`, `→ needs N` clamped 2..6; `unmodified N+` for a raw-face roll, none when every face passes; `1 fails` for dangerous terrain), raw faces bright or faded (`3 wounds:` for a roll in a deal-wounds frame), `Result` (`hits` with `Die.Triggered` counted by rule, `blocked, wounds`, `N ignored, N wounds stand`, `passed`/`cast`/`failed` then ` → {Consequence}`: the change words of the test frame's later roll-less steps, which draw no line of their own) and live amendments (`rerolled ⚁ → ⚄`); a roll-off labels each die by the team it belongs to (`DieLabels`, the tied teams per record) and names `Team N wins` on the record that broke the tie (`CombatLog.Aftermath`); change lines (`N models wounded`, `N models removed`, `unit Fled!` for models shelved unwounded, a condition, `unit · Shaken` on a unit other than the block's actor, `unit gets Rule`); outside actions `Round N`, a player's deployment `Team 1 · unit deployed`, a round end's objective changes one line each (`LogText.RoundChange`), a menu edit `· by hand`, `Undone to: header` (the first block the undo took back that no earlier undo had, else the action it stepped into), the end. Asks, answers, closes, empty steps, frame starts and finishes, and turn starts and ends are not drawn. A roll row wraps to the panel's width (each label keeps a 160 px floor); its expansion holds `RollEntry.Details`, the dice, the rule chips and Undo to here. The dice tray wraps a long line inside its slot and carries all of it as its tooltip.
- Undo: `UndoButton`, left of the log button, shown to every player and hidden for a watcher; `UndoPlan` (`Session.CombatLog.Undo`) picks the last action in the game (the newest effective-log event with an actor, neither an `Undone` marker nor an `AskClosed`, which goes with the answer that closed it), targets the live seq before it, and lists the rolls the undo would take for the "Undo dice rolls?" dialog. Ctrl+Z (`Intent.Undo`) presses it; it sends `Session.UndoToAsync`.
- Input: `TableInput` turns mouse and keys into presence (20 Hz timer), commands and edits. A drag ends when the left button is up (`_Process` reads the button, so a release the table's viewport never hears still drops), and a move that ends with models in hand puts them back (`DropProposed`, from the decision box's `Unhook`). The pointer leaving the table's container for a Hud part clears the hovered unit (`ClearHover`); `HoveredUnit` is the unit a decision-box button names (`HoverUnit`), else the one under the cursor; the wheel over a Hud part never zooms the camera. Picking casts the camera ray and tests each piece's `Bounds` (`Aabb`) with its own slab-method `RayHit`; the table plane is `Plane(Vector3.Up, 0)`. Geometry (collision, containment, movement) is `Tabletop.Geometry`; Godot only casts the ray. Measuring is `TapeMeasure`: Ctrl down anchors the ruler under the cursor (a model's base, a terrain piece's top) and it follows the cursor until Ctrl comes up; the M tool is click, click; H switches 2D/3D (`ClientSettings.MeasureMode`), and the mode rides on the relayed `Measurement` so others read the same number.
- A drag is `DragBodies` (`HeldBody`, `HeldEnd`, `Stationary`, `Walls`, `Models`, `Piece`, `Surfaces`; held pieces lift over spec). Every pick-up starts lifted (`Drag.Level` null): each held model or setup terrain piece goes straight to its target, drawn 0.5" over the highest top under it, models included (`Collision.Hover`), with a ring where it will land (`LandingMarks`): the nearest spot clear of other models' bases (the held ones landed first, in drag order) and of `DragBodies.Walls`, inside a move step only within the model's reach (`Collision.Land`); `Drag.Current` is the landing, which the ruler, the proposal, presence and the drop read. PageDown and PageUp (`Intent.Lower`/`Raise`, `HoldLevel` over the lead piece's `Collision.Surfaces`) step the level one open surface down or up, above the highest lifted again; at a level a model slides along Impassable volumes and other models whose height interval meets its body there (`Collision.Separate`), so it passes under a bridge with room, and rests on its open surface nearest the level. During a move Ask `TableInput.Region` is the Ask's region and `MoveRegions` (`TableInput.Reach`) holds each model's own `MoveReach` (by path, round the other models, walls and the table edge): `MoveRegions.Outline` is the one area it can reach, round difficult terrain within the allowance or through it within the cap (owner ruling), drawn for the lead when the Ask opens and for the held models from each pickup (`TableInput.PickedUp`) on; the ruler follows `MoveRegions.Route` (a bent path is a polyline, `RulerPath.Lift`) and reads its length. Alt places freely: no lifting, no sliding, no stopping, resting nearest the level, the server judges (`move_overlap`, `move_through_models`, `move_separation`) under the enforcement setting; the F1 overlay and the move hint say so. A setup terrain piece in hand (`DragBodies.Piece`, from where it is held at its held yaw) lifted goes straight to the cursor and lands at the nearest spot clear of Impassable pieces; at a level it goes straight to the cursor when its footprint there is free at that height, else slides toward it; Q/E held turn it smoothly, 120° a second, Shift 30° (`CameraFocus.HeldTurn`, as for held models), and a turn into an Impassable piece moves it to the nearest free spot. Built-in `large-sight-blocker` is Impassable (p.11); built-in `ruin` is an Area: Difficult, Cover, BlocksLineOfSight, SeeInAndOut.
- During a move Ask, `TableInput.Proposing` holds the models being positioned: dragging streams proposed ghosts, release sends nothing, and the decision box commits on Enter. A drag's `Grabs` (`DragBodies.Grabs`) are where each piece stood when picked up (a proposed ghost where its node is drawn, so a re-grab does not jump back), for the cursor offsets and Esc; its `Origins` are the projection's positions, for one ruler per held piece and the allowance. A region anchored on a model (`Containment.ExitingId`) over shelf models is a Spawn or Split reserve's `place` Ask (`MoveRuler.IsShelfPlacement`): the note is the Ask's prompt, the ghosts start in rings about the anchor, clear of it by the Ask's `Separation` and skipping spots off the table (`DeployView.Around`), and each answers with its ghost's facing. `TableInput.ModelsDragged` carries a drag frame's held models together, so the decision box gates once a frame. Each held piece has its own yaw (`Drag.Yaws`): Q/E held with no rows turn each held model about its centre (120° a second, Shift 30°), and the answer carries each node's facing. Without Alt each Proposing model's target is held to its reach from its origin (`MoveRegions.Clamp`: the nearest point a path within the allowance, or through one of the Ask's `DifficultVolumeIds` within its `DifficultCap`, reaches), and every one to the cap once any ghost of the move (`TableInput.Proposed`) goes in or through a listed difficult volume along its path (`MoveRegions.Allowance`, p.11), which the readouts and the gate read too; a `MinDistance` is `MoveRegions.Minimum` in the direction the model goes (`MoveRuler.Minimum`, the server's `GfMoves.Minimum`); `MoveRuler.Gate` names how many ghosts are out of range and each contact reason in `TableInput.Violations`, and under `strict` disables the commit and the stop. Contact marks (design `docs/design/client/table-view.md` → Contact marks): the decision box measures its ghosts on every drag and render with `ContactCheck.Move` (a landing on a base, a landing in impassable terrain unless the Ask `IgnoresTerrain`, whatever volumes it lists, so a Flying move's landing is marked as the server judges it, a landing that only a path through a model reaches within the allowance (the unit's capped allowance once the cap holds it; on the table) unless the Ask `PassesModels`, within the Ask's `Separation` of another unit's model, body to body; a unit the mover already stood that close to is left to the server) or, for a deployment, `ContactCheck.Placement` (a base only), and gates Place the same way; `TableInput` measures a hand move with `ContactCheck.Placement` while it is in hand. `ViolationMarks` draws every marked model in `Ui.Warning` (`PieceNode.SetWarning`) with one label per reason over its first model, the held ones first; the decision box's gate line reads each reason as a sentence naming the model (`ContactCheck.Sentence` through `Violations.Subject`), and hides a line that repeats the refusal over it, which a drag of a ghost clears. A commit the server refuses (`CommitHold`: `Remember` before the send, `Sent` with the command id) comes back through `GhostStash` where it was dropped, its moved models marked with the server's detail (`Violations.Refused`) until one is dragged (`Violations.Moved`). Outside one a drag is a hand move, judged under the game's enforcement; under `strict` it does not start. Terrain drags only in Setup (`TerrainLock`): it is locked from the end of setup. From play on an objective marker is locked (`TableInput.Locks`, a `MarkerLocks`): its drag does not start until the marker menu's local Unlock item frees it, and Lock locks it again.
- Play: `GameScreen.Play` builds the Hud over the table and the overlays in it; lobby and setup keep the side panel, which scrolls, with wrapping rows and labels so it never widens past 360 px. `SetupToolbar` holds the Table, Terrain, Markers, Zones and Layouts sections under headings that collapse; Terrain's Clear terrain asks first and sends the draft without its terrain (`ReplaceDraft`); its planet dropdown and Random table button post the draft's size and zones to `POST /v1/layouts/random` and send `ReplaceDraft` of the draft with the laid terrain (a toast names the pieces left unplaced); Layouts' Load layout lists management's predefined tables (`GET /v1/layouts/builtin`) before the account's and sends `ReplaceDraft` of the pick. A selected terrain piece or setup marker shows in `TerrainCard`, in the unit card's `HudLayout` slot and frame, in setup and play (`GameScreen` builds it with the screen; `Layout` places it in the slot below the roster); `SheetFocus` names no unit while terrain is selected, so the unit card gives the slot up and selecting a unit takes it back. In setup the card carries the piece's edits (Facing field and ⟲/⟳ 15°, scale, swap mesh, swap for my asset, reset volumes, remove, each volume's kind, footprint, heights, declarations and notes) and a marker's Remove; in play it is read-only. In setup a right-click on a terrain piece or setup marker opens `MenuModel.ForSetupPiece` (items whose `MenuItem.Edit` builds a setup edit: for terrain Turn left 15°, Turn right 15°, Set facing…, through `MenuModel.TurnInDraft`, then Remove; the terrain card's Facing field and ⟲/⟳ buttons go through the same), and Delete or Backspace (`Intent.Remove`) removes the selected one unless a text field has focus. In play a right-click on a roster row opens `MenuModel.ForRosterUnit` (Set aside / Return to deployment for a shelved Ambush or Scout unit of mine; Put in transport per Transport `Session.DeployInside` names, and Take out of transport while that Transport is on the shelf: hand moves the server judges, passengers spec), and the row reads `in {Transport}` for a unit inside one and `Reserve: {property} ({unit})` (`RosterView.ReserveOf`, the snapshot's `Unit.Reserve`; the unit card shows the same as a chip) for a unit held off the table (every model on the shelf, none wounded) until a property places it; a right-click on a model my open move Ask moves leads with `MenuModel.ForBoarding` (Board transport per `MoveContainment.Enterable`, answering the Ask); a deploy pick lists only units with a model on the shelf (`DeployView.Pickable`); hovering a terrain piece shows its `TerrainLabel` (`TableInput.HoveredTerrain`), and a click selects it into the terrain card. `EndMessage` is the Game over modal over `GameOverView`: it opens once per `game_over` Ask (warn's End or Continue after the final round) with End and Continue answering it (`AnswerAsk`), then "Waiting for the other player" once my team has answered; and once when the game ends (`Projection.Ended`), with the result, reason and scores, Stay (or Esc) closing it and Leave going home through `Session.DisconnectAsync`. The header's Game over button reopens it. Hud parts take keys in `_Input`, before the table's viewport; `TableInput` maps the rest through `Hotkeys.Of` and raises `IntentPressed`; the table's viewport hears keys typed into a Hud or side-panel text field too, so a key pressed while a `LineEdit`, `TextEdit` or `SpinBox` has the root viewport's focus is no hotkey (`TableInput.TextFocused`). Max wounds, where a unit may deploy inside, sight and who can shoot come from the server (`ModelFacts`, `SightAnswer`); rule texts from `GET /v1/properties/{hash}/rules`.
- Replay (`docs/design/client/replay.md`): Home's Replay (a row with `GameSummary.Joined`, `playing` or `ended`; Games I'm in lists `GET /v1/games?joined=true`) calls `Session.ReplayAsync`, which connects on `/ws?watch=1` (the server holds it as a watcher). `Session.Replay` (`ReplayTimeline`) runs over the live log from position 0; `Projection` and `Log` are the replay's, so every part shows its position. `SeekReplay` raises `EventsApplied` for an animated forward step, else `BoardChanged` (the `Animator` drops its queue and glides). Commands and edits throw, undo, sight, presence and pings send nothing, live presence is not shown; live events extend the timeline; a reconnect returns to the position. `ReplayBar` (`HudPart.Replay`, the left column's foot): round, turn, action and step back and forward, Play/Pause at 0.5–8× (`ReplayClock`), a scrubber, the caption. Home goes back to the list.
- Built-in content (spec `2026-10-18-builtin-content-from-server-design.md`): `Main` uses `<user dir>/builtin.json` at start when the cache holds every file it names, else the packed catalog. `ManagementClient.BuiltinVersionSeen` (each response's `Tabletop-Builtin-Version`) feeds `BuiltinSync.Notice` while signed in: a new version fetches `GET /v1/builtin`, downloads the files whose hash `AssetCache` lacks, saves the catalog and `BuiltinContent.Use`s it on the main thread; a failure keeps the catalog in use and waits a minute. `BuiltinContent.TerrainMeshFile`/`TextureFile` give the cached blob for a listed file, else `res://content/builtin/…`. On `BuiltinContent.Changed` `TableView` reloads built-in meshes and the slab texture and `SetupToolbar` refills its lists. Placed pieces keep the volumes copied at placement.
- `WorldFrame` converts the wire frame to Godot: x = X, y = Z, z = -Y; yaw 0 faces +Y (Godot -Z), positive yaw counter-clockwise from above.
- `MeshLoader` parses each GLB file (cache path or built-in) once, on the thread pool (a built-in's template is shared by every game and the warm-up and freed at exit), with levels of detail (`ImporterMesh.GenerateLods`; Godot's runtime import makes none), generates its scene on the main thread within `FrameBudget` as a template, counts the files a table is loading (`Progress`, the loading strip), and hands each piece a `Duplicate()` with the asset's `Orient` applied (a resolved asset is kept, so a later piece or ghost of it builds in the same frame); placement ghosts (`TableView.Ghost`, `PieceNode.SetGhost`) draw the slot's mesh see-through under one shared overlay, with a base ring; the template turns vertex colours on for every surface that has them (Godot's import misses a mesh's first primitive) and takes a node whose surfaces are all alpha-blended out of the shadow pass; `TableView` disposes it, freeing the templates. It fits meshes to a piece's volume. A cached GLB passes `GlbPreflight` before `AppendFromFile` (GLB v2, JSON chunk <= 1 MB, one uri-less buffer, <= 8 embedded PNG/JPEG images <= 4096 per side, accessor and buffer-view ranges inside BIN, each accessor <= 3M elements and <= 64 MB and all of them <= 128 MB, every attribute and morph target at POSITION's count, <= 500k vertices, <= 1M triangles, `extensionsRequired` from `GlbPreflight.AllowedRequiredExtensions`, not EXT_meshopt_compression); any malformed shape or exception is a refusal, which logs and keeps the proxy. Manifest refreshes go through one `CoalescedRefresh`: `RefreshManifest` runs now or joins; a load's unknown id or lapsed URLs join one in flight, else at most one start per 5 s with one trailing refresh shared by the window. A glTF is Y-up and stands upright at pitch 90; a Z-up STL conversion at pitch 0.

## Commands

```bash
dotnet build client/Tabletop.csproj       # or `dotnet build` from the root
./scripts/check-client                    # grep checks, below
./scripts/client                          # build, check-client, launch Godot on Windows
./scripts/godot -e                        # open the editor on the Windows host
./scripts/godot                           # run without building
dotnet test tests/Tabletop.Client.Tests   # the Godot-free core
```

## Conventions and pitfalls

- `src/Core/` is compiled into `tests/Tabletop.Client.Tests` by `<Compile Include="../../client/src/Core/**/*.cs">`. A `using Godot` there breaks the tests; `check-client` fails on it. Core may reference only the three libs and the BCL.
- `check-client` also fails on a colour literal (`new Color(`, `Colors.`, `Color.FromHtml`, a target-typed `Modulate = new(`, and similar) under `src/Hud`, `src/Panels` or `src/Screens`: use `Ui` or a `Variation` (a `Flat` button sets `Variation.FlatButton`; the check does not test that). It also fails on: a physics body or collision shape in `client/scenes`; Godot physics types in `client/src`; a rules-engine type (`Tabletop.GameServer`, `IRulesEngine`, `CommandDispatcher`, `Legality`, and similar) in `client/src`.
- Every `ScrollContainer` sets `VerticalScrollMode = Reserve` (and `HorizontalScrollMode = Disabled`): content whose height depends on its width (wrapping labels, `HFlowContainer`) otherwise flips the bar on and off, and each flip queues another deferred re-layout in the same flush until Godot's message queue overflows ("Object was deleted while awaiting a callback", then a crash). `GameScreen.QueueLayout` also caps itself at four passes a frame and warns past that.
- A change to `CombatLog`, `RollEntry` or `UndoPlan` regenerates `viewer/tests/fixtures/combatlog.json` (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter CombatLogViewerFixture`) and is ported to `viewer/src/lib/play/` until `combatLog.agreement.test.ts` passes; a change to any other `src/Core/` file the viewer ports (`viewer/AGENTS.md` → Layout, `src/lib/play/`) is ported with its test.
- Every outbound socket message is built by a Core function (the list under Layout, the outbound messages); a node only calls it. A new outbound message, or a new control that sends one, is not done until `CallsViewerFixtureTests` writes a case for it (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter CallsViewerFixture`, after the call logs: `tests/Tabletop.Viewer.Tests --filter CallLogFixture`) and `viewer/tests/calls.agreement.test.ts` passes. A difference is fixed in the browser, unless the case shows a Godot bug; then in both, with a test.
- No Godot physics; picking is ray versus AABB.
- Godot's import step wipes `client/.godot/mono/temp/bin/`. Build after an import; otherwise every script fails with "class could not be found". `./scripts/client` builds in WSL first.
- `Directory.Build.props` gives each OS its own `obj/Unix` or `obj/Windows_NT`; a shared `obj/` breaks restore. `TabletopBuildSlot` adds a suffix to `obj/` and `bin/` for the compose server containers; the client does not set it.
- The Godot editor runs on the Windows host, so the client reads and writes in `UserData.Dir` there: a release build uses `OS.GetUserDataDir()` (`%APPDATA%\Godot\app_userdata\Tabletop`), a development build the sibling `Tabletop-dev`, so a dev-stack JWT never reaches production or the reverse. Godot's `logs/` stay under `Tabletop` for both. A release build that finds server addresses in its `settings.json` clears `session.bin` and rewrites the settings without them. The files: `builtin.json` (`BuiltinSync`), `settings.json` (`ClientSettings`: `Animate`, `MutedWindowKinds`, `RememberMe`, `ManagementUrl`, `GameServerUrl`, `LogFilter`, `LogOpen`, `Theme`, `CameraFollow`, `TurnBanner`, `RangeRings`, `MeasureMode`, `WebUrl`, `Sound`, `Volume`, `Display`, `Quality`, `RenderScale`, `VSync`, `Window`), `session.bin` (the remembered JWT, `SessionStore`) and `cache/` (`AssetCache`). Signing in a headless dev run without a password: write the JWT from `POST /v1/dev/sessions` to `Tabletop-dev/session.bin` (on Linux `~/.local/share/godot/app_userdata/Tabletop-dev/`). Settings are presentation only and never reach the server.
- A development build's default URLs use `127.0.0.1`, not `localhost`: Windows tries `::1` first, which does not reach WSL, and .NET waits 21 s before falling back.
- `Session` raises events on the main thread only through `IDispatcher`; tests use `ImmediateDispatcher`.
- `SessionStore.Read` returns null for anything that is not three non-empty dot-separated segments, so a corrupt file never reaches an Authorization header.
- `.tscn`, `.tres`, `.godot` and `.import` files are owned by the editor: hand-edit only when necessary, never reformat. Scenes are written minimal and owned by the editor afterwards.
- No scene may contain a physics body; dev tooling stays out of `client/`, since the editor scans everything under the project root.
- C# only, no GDScript. One world unit is one inch.
- `net10.0` runs under Godot's `net8.0` host because `GodotPlugins.runtimeconfig.json` sets `rollForward: LatestMajor`. If a Godot upgrade breaks C# loading, drop the TFM to `net8.0` first.
