# client

The Godot 4.7 / C# game client and the only project with a Godot dependency. A renderer plus a geometry engine over the server's wire protocol; it has no offline mode and holds no rules.

## Layout

- `Tabletop.csproj`: `Godot.NET.Sdk/4.7.2`, `net10.0`, references `Tabletop.Geometry`, `Tabletop.Content`, `Tabletop.Protocol` only.
- `Tabletop.sln`: the client and the three libs, the solution Godot builds and exports (`<assembly_name>.sln` beside `project.godot`). `export_presets.cfg`: `Windows` (x86_64), `Linux` (x86_64), `macOS` (universal, ad-hoc signed, macOS 12 and later: the .NET runtime's floor); `scripts/release-client` runs them. A release build sets `TabletopVersion` and `TabletopWebUrl` (environment or `-p:`), which the csproj writes as assembly metadata.
- `src/Main.cs`: root node. Builds `Session`, `AssetCache`, `ClientSettings`, `SessionStore`; runs the shader warm-up when its stamp changed, then routes by `SessionPhase` to a scene.
- `src/PerfProbe.cs`, `src/PerfScript.cs`: a development build's frame recorder (performance spec → The Godot client): `TABLETOP_PERF_OUT` (a CSV row per frame), `TABLETOP_PERF_GAME` (enter a game at start; `TABLETOP_PERF_REPLAY=1` its replay, `TABLETOP_PERF_REPLAY_FROM` moved to that position from 8 s in, then `TABLETOP_PERF_REPLAY_STEP` an animated action forward every that many seconds of game time, `TABLETOP_PERF_ZOOM` the table camera's distance at each), `TABLETOP_PERF_SECONDS`, `TABLETOP_PERF_BENCH` (the graphics bench); `<csv>.mark` and `<csv>.shot` for a driving script; each row also carries the frame number, Godot's pipeline-compilation counters, the process and physics monitors, `script_ms` (the main thread's `_Process` span), `flush_ms` (from there to the draw), `draw_ms` (the draw's submission), `physics_steps`, `before_physics_ms` and `after_physics_ms` (the physics step's deferred calls, where the dispatcher's turn and the Hud's notifications land) and `probes` (`PerfProbe.Time`/`Timed` around a suspect, per frame `name=ms@kbxN`: milliseconds, kilobytes allocated, calls); `TABLETOP_PERF_SCRIPT=play` runs `PerfScript`, the scripted play session, an activation then the next team's (Measuring frame times, below). A release build never reads them.
- `src/Core/`: Godot-free logic.
  - `Session`: the one object that outlives screens: login, `ManagementClient`, the socket, `EventApplier`, draft, presence; `Session.Replay.cs` the replay.
  - `ReplayTimeline` (`ReplayUnit`, `Stops`), `ReplayClock`: a replay's position in the log and its playback. `ReplayBarView`: the bar's labelled step buttons, the round ticks, the caption (the latest live block header).
  - `ManagementClient`: the one HTTP client over management's `/v1`; `ManagementDtos`. `ClientHttp`: `Main`'s one `HttpClient`, decoding Brotli, gzip and deflate.
  - `IGameSocket`/`ClientGameSocket`: the socket seam and its `ClientWebSocket` implementation, offering permessage-deflate (`SocketCompression`; `Connect` and `Reauth` sent uncompressed).

## How it works

- `Main` swaps one screen at a time on `Session.PhaseChanged`: `LoggedOut` to Login, `LoggedIn` to Home, `UpdateRequired` to UpdateRequired, anything else to Game.
- `UpdateRequiredScreen` names `ClientSettings.DownloadUrl` (`WebUrl` + `/download`) and opens it. `ClientSettings.Default` is `DefaultFor(BuildInfo.Current)`: a release build reaches management at its web origin and the socket at `wss://<host>/ws`; a development build the local stack. A release build ignores persisted server addresses and never writes them (`ClientSettings.Load`/`Save` take the `BuildInfo`).
- Management: `ManagementClient` sends the version header on every request and the bearer once `Jwt` is set. `Session` refreshes the JWT every 60 s from `Main`; a failed refresh backs off one minute.
- Game socket: `ClientGameSocket` raises `FrameReceived`/`Closed` on its own thread. `Session` posts them through `IDispatcher` and ignores frames from a socket that is no longer current.
- A picker lists every army with its `Edition` (`LobbyView.ArmyLabel`, `ArmySummary.Edition`); one whose edition is not the game's (`RuleSets.EditionOf(gameRules)`) is disabled with the reason "3.5 list" or "3.6 list", the army's own field; the game server refuses it either way. The game's rule set is shown by the server's name, never its id.
- Zone legs come from Welcome: `Session.Zones` is `Welcome.Zones`, and `ZoneNode` and `CameraFocus.TeamSide` resolve zone shapes with it. Nothing in the client names an edition.
- Terrain rules come from Welcome: `Session.TerrainRules` is `Welcome.TerrainRules` (or `RulesOptionsMessage`'s), one sentence per declaration of what it does to a unit, which the play terrain card shows under each effect.
- Terrain words come from Welcome: `Session.TerrainWords` is `Welcome.TerrainWords` (by declaration name), and `TerrainLabel` (`Of`, `FlagsOf`, `DeclarationsIn`), `TerrainCardContent.Of` and `TerrainGroups` (`Of`, `Summary`, `Matches`, a one-declaration group's title) show the server's word, falling back to their own (`TerrainLabel.WordOf`). `MoveRegions` and `ContactCheck` add `MoveRegion.SteepVolumeIds` the model starts outside to its difficult volumes (`Movement.SteepEntering`).
- `Session.Handle` takes `Welcome`, then the board, then events. Events go into an `EventApplier`; `Session.Projection` is its `Projection`, or the `ProjectTo(seq)` prefix while an undo preview is pending.
- A `ProjectionDesyncException` triggers one resync per log position (`_desyncFloor`). A lost socket reconnects with backoff 1, 2, 5, 10 s unless the user closed it.
- `Session.CatchingUp` is true from a reset or a received board until a `ModelFacts` frame or an empty events page; floating results, turn banners and camera follow stay silent while it holds.
- `Session.EventsApplied`, `GameChanged`, `BoardChanged`, `FactsChanged`, `RefusedReceived` are what panels subscribe to. Session outlives panels: every subscription comes off in `_ExitTree`.
- Renders are coalesced: each of those four changes also marks `Session.Frame` with a `RenderCause`, and `Frame.Render(causes)` fires once per dispatcher turn (one deferred call on Godot), so a frame's batches give one render. A part that redraws from the current state subscribes to `Frame.Render` and filters on its causes (`HeaderBar`, `Roster`, `UnitCard`, `DecisionBox`, `DiceTray`, `UndoButton`, `CombatLogPanel`, `EndMessage`, `UnitMarkerNodes`, `ModelMarkNodes`, `HoverLabels`, `RangeRingNode`, `TargetLines`, `SightLines`, `GameScreen.RefreshAll`). A part that reads the batch keeps `EventsApplied` (`FloatingText`, `SoundPlayer`, `TurnBanner`, the decision box's sealed reveal, queued in `SealedReveals` until a render shows it, `Animator`, the camera follow, `TableView`).
- Graphics: `GraphicsApplier` sets the window (borderless Fullscreen or the saved windowed rect, `Main` saving it each second it changed and on close; first start 1280×720 from `project.godot`), VSync, the frame-rate limit (`Engine.MaxFps`) and the directional shadow atlas from `Main`, and the table's `SubViewport` (`Msaa3D`, FSR 1 `Scaling3DScale` below 100 %, `MeshLodThreshold`), environment (SSAO) and key light (splits, max distance, angular size for soft shadows) from `TableView`, on `SettingsChanged`. The Hud is in the root viewport at full resolution. With no Quality saved, `Main` picks `GraphicsSettings.FirstQuality` for the GPU (`GraphicsApplier.Gpu`) and saves it.
- Sound: `SoundPlayer` (built beside `FloatingText` in `GameScreen.Play`) feeds each `EventsApplied` batch to `SoundCues.OnBatch`, silent while `Session.CatchingUp`, on an empty batch (a replay's jump or step back, which redraws and then raises one) or when the batch holds an `Undone`, each of which reseeds the wound totals and open frames (an undo also drops cues still waiting); a replay's animated forward steps (Play at 1× or slower, Step and Action forward) play. Shoot: a `hit` roll under `shooting` is a volley of one shot per die (the variant by the weapon group the group's first weapon's name falls in, `SoundCues.VariantOf`: plasma, ballistic, las, heavy, flame), then Impact or Miss by its successes; Melee and Whiff: a `hit` roll under `melee` is a volley of one strike per hit and one whiff per miss, in die order; a volley's die sounds are 95 ms apart with ±12 ms jitter and ±6 % pitch and 0 to -3 dB level from a hash of the frame id and die index, compressed to fit `SoundCues.MaxVolleySeconds` (5 s) down to 30 ms, past which it plays 167 of the dice; Block: a `defense` roll with every die blocked; Wound: a `defense` roll letting a wound through, a `WoundsSet` whose total rose, or a model leaving the table for the shelf; Fizzle: a failed `casting` roll; CastFriendly or CastEnemy: a casting frame's `targets` answer naming a piece of the caster's team (`Names.TeamOfUnit`) or another; Move: a `ModelsMoved` landing a model on the table (step, hand move, deployment). Cues play in log order, each after the one before by `SoundCues.Gap` (0.4–0.5 s, the dice tray's tumble; 0.15 s between back-to-back volleys), and every cue but a volley's at most once between volleys, so a shot reads volley, hit or miss, block or wound. Sixteen `AudioStreamPlayer` voices play volleys and eight the other cues (an idle one, else the oldest). `Settings.Sound` (default on) and `Volume` (0-100, default 70) gate and scale it. `SoundPlayer.Cued` raises each batch's cues, Sound on or off, for `BattleFx`; `GameScreen.Play` frees the player with the play panels.
- Feedback: every refusal toasts `Feedback.Refusal`, every close `Feedback.Closed`; `Session.LastCloseReason` is player text and Home prints it. A `1008` (the socket's JWT expired) refreshes the JWT before the reconnect. `Session.IsWatching` (a replay, an admin watcher, or from `playing` on an account with no team, except while deployment waits for players) stops presence and pings, drags, the piece, team and roster menus and Undo, and the header says the player watches. `Session.RenameAsync` patches `/v1/account`. Dialogs that take text (`PieceMenu.AskText`, `AskInteger`, Home's name fields) focus their field, confirm on Enter and stop at the servers' lengths; Leave the game asks first; the game menu's Leave game (the only one in a game; the table's right-click menu has none) opens the same question. Home's End game and Delete game (`HomeView`'s ▸ menu, `ManagementClient.EndGame`/`DeleteGame`) are the creator's, asked first, and Leave (`LeaveGame`) is asked first too.
- Commands: `SendCommandAsync(command, id)` takes the caller's message id so a `Refused` arriving before the send's continuation can still be matched. `SendEditAsync` is for setup edits. While `Reconnecting` both queue (`Session.Queueing`, at most 16) and go out after the next `Welcome`, or fail when the session goes home. A welcomed socket gets `Reauth` with each refreshed JWT. The decision box keeps a move's or deploy's ghosts across a reconnect (`GhostStash`) for the same Ask or unit.
- Table redraw: `TableView.Redraw` runs on `BoardChanged`, `GameChanged` and each `EventsApplied` batch, and diffs each layer through `BoardDiff`. Every node (`IDrawn<T>`) keeps the item it was built from: a removed id's node leaves the tree at once, a new id gets a node, a reshaped one (terrain mesh or volumes; marker kind, diameter, label, visual or control colour; zone shape, table size, legs or colour) is replaced, and a kept one only takes its transform, which also snaps back a refused drag. A held id (`IsHeld`) is left alone.
- Animation: `Animator` feeds `EventsApplied` into `AnimationQueue`. The projection is already current; the queue only paces playback. `Settings.Animate` false plays everything at once, true one event per call: every model the event moves glides at once (`GlidePlan.Of`, which follows the frames as events play), and the next event waits for the last. A Walk eases in and out with a low step bob, 0.35–0.9 s by distance; a Charge (the charging unit's own move in its `charge` frame) pulls back up to 0.3", accelerates into contact, overshoots up to 0.12" and settles, 0.35–0.6 s; a Place (onto the table from the shelf) drops 1.2" in 0.3 s; yaw turns along the shortest arc (`GlideCurve.At`, driven by a `TweenMethod`). `Animator.Played` raises each event as it plays. The table has already redrawn the batch, so the `Animator` redraws only after a glide ends or when it consumed the player's own drop holds; `FloatingText` subscribes to `EventsApplied` before the `Animator` is made, so it reads each batch first.
- Battle effects (sound spec → On the table): `BattleFx`, a child of the table, plans `BattleEffects.Plan` from `SoundPlayer.Cued` (melee, block, wound) and from `Session.Fired` with the same cues (shots, matched by `Shot.FrameId`), and plays each on its own clock at the cue's delay: muzzle flash and recoil, tracer, strike with sparks, dust puff, melee jab, deflection, a wounded model's shake (`PieceNode.SetJolt` moves what a model draws, the node staying on its placement), a removed model's fall. `TableView.Removing` hands it a node an events batch takes off the table; it keeps the node standing until its Wound cue fells it, or frees it the next frame when no cue does (an undo, a silent batch). Flashes, puffs and flames are additive soft billboards; meshes are shared and materials cached per colour, faded by `GeometryInstance3D.Transparency`; sparks fly computed arcs. Settings.Animate off draws only the aim beams. `WarmupScene` draws one of each effect mesh and material.
- Wound numbers: `WoundNumbers` (Core) reads each `EventsApplied` batch for `WoundsSet` totals that rose on a model still on the table and under its `Session.MaxWounds` (one removed or killed by the same wounds, or healed, shows nothing) and gives one `-1` per wound (`WoundNumber`: model, head = placement + slot height, `Index`, `Delay` = 0.35 s × index); silent while `Session.CatchingUp`, on an empty batch (a replay's jump or step back) and on one with an `Undone`, each of which reseeds the totals, as `SoundCues`. `FloatingText` shows them when the `Animator` plays their event, with `Settings.Animate` on: red `Label`s with a dark outline (one shared `LabelSettings`, labels pooled) projected over the head, rising 110 px and fading over 2.5 s (`WoundNumbers.Look`); it processes only while a result or number floats. They replace the unit's `-k wounds` floating result.
- Teams (game-flow spec → One account, several teams): `Session.MyTeamIds` is every team the account holds (`Seats.Teams`: the rows sharing the account of Welcome's row), and `MyTeamId` the team acted for now (`Seats.Acting`: the team of the first open Ask waiting on one of mine, else the active team if mine, between turns (a round boundary's Ambusher picks too) the latest of mine to start a turn or answer an Ask in the live log, else my first; the decision box places a deploy pick made by any team of mine), so the decision box, unit card, roster, Tab cycle and range rings follow it. Holding several, the decision box and the game-over modal say "Playing as Team N" (`Seats.PlayingAs`), answers name their team (`AnswerAsk.TeamId`), and the camera goes to the acting team's side when it changes with no frame open, by the follow rule (`CameraFocus.SideOnSwitch`, `TeamSide`); inside an activation the Asks pass between the teams and the camera stays. The lobby's team columns (`TeamColumns`) carry Join, which adds a seat for my account (one account playing both sides solo; it never moves my seat), and a row's ▸ menu and drag, which move a seat (Leave Team N on my row while I hold several); a team another account holds shows Join disabled with "Ann holds this team: the creator adds players to it."; `LobbyView.Armies` gives "Your army", one picker per team held, on my row of each column; every army picker (lobby, waiting for players; the create dialog has none) lists `LobbyView.ArmyOptions`: the game's edition first, another edition's armies disabled with the reason (`ReimportReason`, `NoLongerServedReason`; `LobbyPanel.AddArmies` fills an `OptionButton`), the server refusing them either way; the columns name each member's army (`Participant.ArmyName`) with the game's edition.
- Team games (rulebook p.50; owner ruling: "Either player from the team can take the activation across any unit in their team."): every Ask to my team is mine, with every unit of the team; `DeployView.MidDeploy` gives the team's deploy pick to every player of the team.
- Waiting for players: `Session.WaitingTeams` (`WaitingForPlayers` over the board and an empty log). While it holds there is no side panel: `WaitingPanel` takes the decision slot (`GameScreen.Layout` places it in `HudPart.Decision`; the decision box draws nothing then) with the quiet band "Deployment waits for every team" over the compact team columns (`WaitingView.Columns`: each band reads Ready, Needs a player or Needs an army, the members and their armies, and inside the column Join on a team no one holds or a dropdown of my armies on a team of mine with none, as in the lobby: picking one sends `PickArmy`), and the header reads "Deployment waits: …". `GameScreen` keeps the panel and calls `WaitingPanel.Refresh` on each game info and board, which rebuilds the columns only when what they show changes (`WaitingView.Changed`), so an open dropdown survives unrelated updates and a picked army clears its line once the board holds it; `GameScreen` rebuilds when a board ends the wait.
- Ask: `AskViewModel.Mine` picks the lowest-id open Ask addressed to `MyTeamId` that the team has not answered; a watcher (no team) gets none. `ModeOf(LegalSet)` maps `Options`, `PieceSelection`, `Allocation`, `Assignment`, `MoveRegion`, `TokenSpend`, `Confirmation` to `AskMode`. `DecisionBox`, in the right column above the undo and log buttons, over `DecisionView` and `DecisionCard` (its body scrolls; `DecisionBox.Place`), draws my Ask as a card: a title band in the answering team's colour with the Ask's icon and title and the ⌨ that opens the key overlay, the body per mode (activation tiles grouped by unit, option tiles, the move's allowance bar, target chips with the target's band, the casualty counter and pips, shelved units as rows, token steppers), gate reasons only while they hold, and the actions at the foot, the primary lit, each with its key cap; an Ask not mine is a quiet band per waiting team (`DecisionCard.Quiet`), and a sealed Ask's reveal a band and chip per team. It renders the mode (hovering an option's button lights its pieces in `Palette.Hovered` and darkens the rest of the Ask's glow, so same-named units tell apart, and when the option names one unit (`DecisionView.UnitNamed`) hovers it through `TableInput.HoverUnit`: its hover label over it and, for an enemy, the enemy strip, until the pointer leaves the button; an option's `AskOption.Note` once, in warning colour, under its unit's options; `UnitCard` shows the same note through `DecisionView.NoteOf`) and answers with `SendCommandAsync(AskAnswers.Answer(ask, answer, team), id)`. A `Refused` for its last command shows as an orange refusal line and re-renders.
- The play log is `CombatLog` over `Session.Log` in `CombatLogPanel` inside `LogDrawer`; the panel renders only while the drawer is open (`CombatLogPanel.Shown`). It draws `LogSheet` (the log as plain text, a paragraph per entry, two spaces of indent per block) through `LogBbcode` into one selectable `RichTextLabel`: a drag selects across any number of entries and Ctrl+C or the right-click menu copies plain lines as drawn (the tags only draw: `[s]` an undone entry, `[color]` a faded one or a block header's team, `[bgcolor]` the picked one, `[url=i]` each line's paragraph); the text is set only when it changed, and the scroll stays at the end while it was there. A left click that selects nothing picks the paragraph under it (`MetaClicked`; tinted, its pieces lit on the table) and gives the focus back; the head's Undo to here (hidden for a watcher) undoes to the picked entry, Copy puts `LogSheet.Text` of the panel on the clipboard; a cast block's line carries its spell's text as the tooltip. `Session.CombatLog` builds it once per log state (log, count, last seq, `PendingUndoTo`, game, projection instance) and hands the same `CombatLogState` to the panel (`Entries`), the dice tray (`Latest`; a click on it `Reveal`s the roll: picked and scrolled to) and the undo button (`Undo`). The tray's 0.4 s tumble changes its faces in place (`DiceFaces.SetRaw`).
- Log entries (combat-log spec → The log; `CombatLog`, `CombatLog.Words`, `CombatLog.Attacks`): an action header `R2 · Team 1 · unit · Charge → target · moved 7.5"` (`Hold → shoots target`; targets from nested frames of the same actor and the action frame's own `SelectedPieces` answers; `moved` sums each model's moves) with its entries beneath; a cast inside it is a nested block `Cast Hex → target` (`ActivationBlock.Nested`); one `RollEntry` per `RollRecord`, tagged with its attack (`AttackTag`: the frame that pushed the `resolve-hits` frame above it, else its own; actor, targets, melee, the rule that dealt hits with no weapon, weapons, `WoundMultiplier` from its assign steps' `wound_multiplier`) and its step's `hit_multiplier`; `Title` (`RollWords.Label` and `RollWords.Target`), `Result`, `Consequence` (a test's later roll-less steps' change words, which draw no line of their own), live amendments, roll-off `DieLabels` and `Team N wins` (`CombatLog.Aftermath`); change lines (`N models wounded`: models whose wounds the step changed, from `WoundsBefore`, a pass over the log ahead of the build; `N models removed`, `unit Fled!`, `unit · Shaken`, every condition naming its unit, `unit gets Rule`; `LineEntry.Worked` lists each model with the wounds the step put on it, or `removed`); outside actions `Round N` (round 0 and `phase_started` draw none), a player's deployment `Team 1 · unit deployed`, a round end's objective changes (`LogText.RoundChange`), a menu edit `· by hand`, `Undone to: header`, the end. Asks, answers, closes, empty steps, frame starts and finishes, and turn starts and ends are not drawn. The dice tray wraps a long line inside its slot and carries all of it as its tooltip.
- Log text (`LogSheet`, `LogSheet.Detail`): consecutive rolls of one attack holding a hit roll or a block are one paragraph, `{unit} → {targets}[ (melee)|(Rule)]  H: {block dice, else hits scored with extra hits × multiplier}  W: {(failed blocks + extra wounds) × wound multiplier − wounds ignored}  with cover/N` with its rolls per wound under it; any other roll `{Unit · }{Label} {Target}: rolled {faces}, {result}` and its amendments; a block header and a line as their text. Detailed (the head's checkbox, `ClientSettings.LogDetailed`, in `Variation.Mono`): an attack's head and weapons (`WorkedLines.Attack`), per hit roll `Hit roll · {target} (N dice)` and a `1 … 6` table of its faces as rolled (`LogSheet.Table`), each reroll or edit (a line for one die, else a table), each rule its faces set off as one line, no table (`+2 hits (Relentless)`, `+1 wound (Shred)`, `Rending (6s: 2 dice)`; a rule rolling dice of its own is its own record and table), `X hits · Y bonus hits` (or `Rule: N hits`), then each block `Defense 5+ · AP(1) -1 · Cover +1 · needs 5+ (N dice)` (`LogSheet.Threshold`: the stat, changes, what a suppression took away, cover a rule took away, each modifier with its own sign, `needs`; no cover reads nothing) over its table, each roll per wound with `N ignored`, `Wounds ×N` (Deadly), `H: X  W: Y`, `Rules:`; any other roll its target, `rolled N` or a table, its result; a change line each model. A paragraph of several lines ends with an empty line. The filter still applies.
- Undo: `UndoButton`, left of the log button, shown to every player and hidden for a watcher; `UndoPlan` (`Session.CombatLog.Undo`) picks the last action in the game (the newest effective-log event with an actor, neither an `Undone` marker nor an `AskClosed`, which goes with the answer that closed it), targets the live seq before it, and lists the rolls the undo would take for the "Undo dice rolls?" dialog. Ctrl+Z (`Intent.Undo`) presses it; it sends `Session.UndoToAsync`.
- Input: `TableInput` turns mouse and keys into presence (20 Hz timer), commands and edits. A drag ends when the left button is up (`_Process` reads the button, so a release the table's viewport never hears still drops), and a move that ends with models in hand puts them back (`DropProposed`, from the decision box's `Unhook`). The pointer leaving the table's container for a Hud part clears the hovered unit (`ClearHover`); `HoveredUnit` is the unit a decision-box button names (`HoverUnit`), else the one under the cursor; the wheel over a Hud part never zooms the camera. Picking casts the camera ray and tests each piece's `Bounds` (`Aabb`) with its own slab-method `RayHit`, and `TablePick` chooses: a model the ray enters, else a model within `TablePick.SlopPixels` of the pointer on screen, else an objective or setup marker that may be dragged now (`MarkerLocks`) whose disc holds the point where the ray meets its plane (`TablePick.OnDisc`), so an unlocked marker under terrain is grabbed, else the nearest terrain piece or locked marker entered; a terrain piece is entered by its volumes' prisms (`TablePick.EnterPrism`: footprint at its yaw and scale, bottom to top), the box only the broad phase, so a tall or turned piece beside the pointer never takes it from the piece under it; the table plane is `Plane(Vector3.Up, 0)`. Geometry (collision, containment, movement) is `Tabletop.Geometry`; Godot only casts the ray. Measuring is `TapeMeasure`: Ctrl down anchors the ruler under the cursor (a model's base, a terrain piece's top) and it follows the cursor until Ctrl comes up; the M tool is click, click; H switches 2D/3D (`ClientSettings.MeasureMode`), and the mode rides on the relayed `Measurement` so others read the same number.
- Picking models (in-game UX spec → Moves): `TableInput.Picks` keeps a `ModelPicks`, which is the selection's model ids (lit as the selection is, sent in presence). A Shift press is decided by `ModelPicks.ShiftPress` once it comes up or travels `DragThreshold`: up unmoved, Shift+click on a model of my team (`Session.MyTeamIds`) toggles it; travelled from a model of my team, that model alone is in hand (`BeginDrag` from the press), the rest of its unit standing as `DragBodies.Stationary`, and the picks keep it or start over with it (`ModelPicks.ShiftHeld`); travelled from anywhere else, it draws a `ReferenceRect` on a `CanvasLayer` and on release adds my models whose base centre projects inside it (`ModelPicks.Boxed`: one unit's, the unit with most inside, on a tie the one nearest the press; another unit starts over). A plain drag on a picked model holds the picks and the rest of the unit stands as `DragBodies.Stationary`; on any other model it holds the whole unit and clears them. A plain click on the table, a change of the decision box's Ask or placement (`TableInput.ClearPicks`) and Esc clear them; the decision box leaves Esc to the table while `HasPicks`.
- A drag is `DragBodies` (`HeldBody`, `HeldEnd`, `Stationary`, `Walls`, `Models`, `Piece`, `Surfaces`; held pieces lift over spec). Every pick-up starts lifted (`Drag.Level` null): each held model or setup terrain piece goes straight to its target, drawn 0.5" over the highest top under it, models included (`Collision.Hover`), with a ring where it will land (`LandingMarks`): the nearest spot clear of other models' bases (the held ones landed first, in drag order) and of `DragBodies.Walls`, inside a move step only within the model's reach (`Collision.Land`), and in a charge Ask drawn flush against a `ContactWith` model it lands within the Ask's `ContactGrace` of (`DragBodies.Abutment`, `Collision.Abut`), where the server's `GfMoves.ChargeLanding` ends the charge; `Drag.Current` is the landing, which the ruler, the proposal, presence and the drop read. PageDown and PageUp (`Intent.Lower`/`Raise`, `HoldLevel` over the lead piece's `Collision.Surfaces`) step the level one open surface down or up, above the highest lifted again; at a level a model slides along Impassable volumes and other models whose height interval meets its body there (`Collision.Separate`), so it passes under a bridge with room, and rests on its open surface nearest the level. During a move Ask `TableInput.Region` is the Ask's region and `MoveRegions` (`TableInput.Reach`) holds each model's own `MoveReach` (by path, round the other models, walls and the table edge): `MoveRegions.Bands` is the one area it can reach, round difficult terrain within the allowance or through it within the cap (owner ruling), in three bands by what getting there costs (`MoveReach.Bands` over the Ask's `DangerousVolumeIds`, `UnstableVolumeIds` and `UnstableOver`; `MoveBandLook`: clear in the team colour, difficult muted, dangerous striped in the terrain's dangerous colour; `MoveRegionNode.ShowBands`), drawn for the lead when the Ask opens and for the held models from each pickup (`TableInput.PickedUp`) on; the ruler follows `MoveRegions.Route` (the path the server measures, round the dangerous ground the Ask names when that fits, `Movement.Measured`; its fields settled on the pool by `Prepare`; a bent path is a polyline, `RulerPath.Lift`) and reads its length. Alt places freely: no lifting, no sliding, no stopping, resting nearest the level, the server judges (`move_overlap`, `move_through_models`, `move_separation`) under the enforcement setting; the F1 overlay and the move hint say so. A setup terrain piece in hand (`DragBodies.Piece`, from where it is held at its held yaw) lifted goes straight to the cursor and lands at the nearest spot clear of Impassable pieces; at a level it goes straight to the cursor when its footprint there is free at that height, else slides toward it; Q/E held turn it smoothly, 120° a second, Shift 30° (`CameraFocus.HeldTurn`, as for held models), and a turn into an Impassable piece moves it to the nearest free spot. Built-in `large-sight-blocker` is Impassable (p.11); built-in `ruin` is an Area: Difficult, Cover, BlocksLineOfSight, SeeInAndOut.
- During a move Ask, `TableInput.Proposing` holds the models being positioned: dragging streams proposed ghosts, release sends nothing, and the decision box commits on Enter. A drag's `Grabs` (`DragBodies.Grabs`) are where each piece stood when picked up (a proposed ghost where its node is drawn, so a re-grab does not jump back), for the cursor offsets and Esc; its `Origins` are the projection's positions, for one ruler per held piece and the allowance. A region anchored on a model (`Containment.ExitingId`) over shelf models is a Spawn or Split reserve's `place` Ask (`MoveRuler.IsShelfPlacement`): the note is the Ask's prompt, the ghosts start in rings about the anchor, clear of it by the Ask's `Separation` and skipping spots off the table (`DeployView.Around`), and each answers with its ghost's facing. `TableInput.ModelsDragged` carries a drag frame's held models together, so the decision box gates once a frame. Each held piece has its own yaw (`Drag.Yaws`): Q/E held with no rows turn each held model about its centre (120° a second, Shift 30°), and the answer carries each node's facing. Without Alt each Proposing model's target is held to its reach from its origin (`MoveRegions.Clamp`: the nearest point a path within the allowance, or through one of the Ask's `DifficultVolumeIds` within its `DifficultCap`, reaches), and every one to the cap once any ghost of the move (`TableInput.Proposed`) goes in or through a listed difficult volume along its path (`MoveRegions.Allowance`, p.11), which the readouts and the gate read too; a `MinDistance` is `MoveRegions.Minimum` in the direction the model goes (`MoveRuler.Minimum`, the server's `GfMoves.Minimum`); `MoveRuler.Gate` names how many ghosts are out of range and each contact reason in `TableInput.Violations`, and under `strict` disables the commit and the stop. Contact marks (design `docs/design/client/table-view.md` → Contact marks): the decision box measures its ghosts on every drag and render with `ContactCheck.Move` (a landing on a base, a landing in impassable terrain unless the Ask `IgnoresTerrain`, whatever volumes it lists, so a Flying move's landing is marked as the server judges it, a landing that only a path through a model reaches within the allowance (the unit's capped allowance once the cap holds it; on the table) unless the Ask `PassesModels`, within the Ask's `Separation` of another unit's model, body to body; a unit the mover already stood that close to is left to the server) or, for a deployment, `ContactCheck.Placement` (a base only), and gates Place the same way; `TableInput` measures a hand move with `ContactCheck.Placement` while it is in hand. `ViolationMarks` draws every marked model in `Ui.Warning` (`PieceNode.SetWarning`) with one label per reason over its first model, the held ones first; the decision box's gate line reads each reason as a sentence naming the model (`ContactCheck.Sentence` through `Violations.Subject`), and hides a line that repeats the refusal over it, which a drag of a ghost clears. The shader warm-up draws only files on hand (`fetch: false`), its board on the table's wood when no print is, and dresses `WarmupGlb` stand-ins in each grain so the terrain materials compile without built-in meshes. Placed pieces keep the volumes copied at placement.
- `WorldFrame` converts the wire frame to Godot: x = X, y = Z, z = -Y; yaw 0 faces +Y (Godot -Z), positive yaw counter-clockwise from above.
- `MeshLoader` parses each GLB file (cache path or built-in) once, on the thread pool (a built-in's template is shared by every game and the warm-up and freed at exit), with levels of detail (`ImporterMesh.GenerateLods`; Godot's runtime import makes none), generates its scene on the main thread within `FrameBudget` as a template, counts the files a table is loading (`Progress`, the loading strip), and hands each piece a `Duplicate()` with the asset's `Orient` applied (a resolved asset is kept, so a later piece or ghost of it builds in the same frame); placement ghosts (`TableView.Ghost`, `PieceNode.SetGhost`) draw the slot's mesh see-through under one shared overlay, with a base ring; the template turns vertex colours on for every surface that has them (Godot's import misses a mesh's first primitive) and takes a node whose surfaces are all alpha-blended out of the shadow pass; `TableView` disposes it, freeing the templates. It fits meshes to a piece's volume. A cached GLB passes `GlbPreflight` before `AppendFromFile` (GLB v2, JSON chunk <= 1 MB, one uri-less buffer, <= 8 embedded PNG/JPEG images <= 4096 per side, accessor and buffer-view ranges inside BIN, each accessor <= 3M elements and <= 64 MB and all of them <= 128 MB, every attribute and morph target at POSITION's count, <= 500k vertices, <= 1M triangles, `extensionsRequired` from `GlbPreflight.AllowedRequiredExtensions`, not EXT_meshopt_compression); any malformed shape or exception is a refusal, which logs and keeps the proxy. Manifest refreshes go through one `CoalescedRefresh`: `RefreshManifest` runs now or joins; a load's unknown id or lapsed URLs join one in flight, else at most one start per 5 s with one trailing refresh shared by the window. A glTF is Y-up and stands upright at pitch 90; a Z-up STL conversion at pitch 0.

## Commands

```bash
dotnet build client/Tabletop.csproj       # or `dotnet build` from the root
./scripts/check-client                    # grep checks, below
./scripts/client                          # build, check-client, launch Godot on Windows
./scripts/godot -e                        # open the editor on the Windows host
./scripts/godot                           # run without building
dotnet test tests/Tabletop.Client.Tests   # the Godot-free core
```

Look at a game position without sending anything: sign in a participant of the game (`POST /v1/dev/sessions`, the JWT into
`$XDG_DATA_HOME/godot/app_userdata/Tabletop-dev/session.bin`, `"rememberMe": true` in `settings.json` beside it), then run
`TABLETOP_PERF_OUT=<dir>/perf.csv TABLETOP_PERF_GAME=<id> TABLETOP_PERF_REPLAY=1 TABLETOP_PERF_REPLAY_FROM=<position>
TABLETOP_PERF_ZOOM=14 TABLETOP_PERF_SECONDS=25 godot --path client --rendering-driver opengl3` (`DISPLAY=:0` under WSLg); the
replay moves to the position 8 s in, and touching `<dir>/perf.csv.shot` writes `perf.csv.shot.png`.

## Spacing

Every separation, margin and content margin is a step of `Space` (`src/Theme/Space.cs`): `XS` 4, `S` 8, `M` 16, `L` 24, `XL` 32,
`XXL` 48; 0 means none. A container's padding is smaller than the gap to its siblings, and related items sit closer than unrelated ones
(label and value `XS`–`S`, rows `S`, groups `M`–`L`, sections `XL`–`XXL`); the Hud over the table keeps to `XS`–`M`, full-screen pages
(Home, Login, lobby) use the upper steps. Fixed control sizes and borders are not spacing. Where a layout breaks, change the layout, not
the scale. Spec `docs/superpowers/specs/2026-11-21-spacing-rules-design.md`; `./scripts/check-client` fails on a numeric spacing argument
under `src/{Hud,Panels,Screens,Theme}`.

## Driving a game by eye

To look at Hud states one after another (selections, Asks, team switches) in a game you may answer: clone the perf template
(`7e000000-0000-4000-8000-000000000001`, one account on both teams; `/tmp/clone.sql` in the Postgres container, as Measuring
frame times) and sign in its account (`POST /v1/dev/sessions` with `{"name":"perf-frames-b"}`), then run
`TABLETOP_PERF_GAME=<clone> godot --path client --rendering-driver opengl3 --write-movie <dir>/f.png --fixed-fps 10 --quit-after <n>`
under `DISPLAY=:0`, keeping only the newest frames while it writes (one 1280×720 PNG a frame). The window is 1600×900 and the frames
1280×720: `xdotool mousemove --window <id>` takes frame coordinates × 1.25. Delete the clone after.

## Measuring frame times

`PerfScript` plays a fixed session through real input (hover sweeps, T, a selection, V, a pan, Advance, a drag, the move, Shoot, a target,
the volley, the casualties, then the next team's selection, Advance, drag and move: a phase's second time is what every later turn pays) and
names each phase in the CSV's `bench` column. It needs a game that opens on the acting team's activation Ask with Hold,
Advance, Rush as 1, 2, 3 and a shooting unit with targets in range, held by the signed-in account (one account on both teams works): clone
a game and cut its log there (`game.game_event` past that seq deleted, the participants' `account_id` set to the dev account), since the
script answers Asks. Measure an export, not the editor's debug build:

1. Copy the tree (`git archive`) to a scratch folder, clear `exclude_filter` in its `export_presets.cfg` (a dev export then packs the
   built-in terrain), seed `client/.godot` from `build/godot-cache`, `godot --headless --path client --import`, `dotnet build`, then
   `godot --headless --path client --export-release Linux <out>/Tabletop.x86_64` (ExportRelease: optimized C#, release template; no
   `TabletopWebUrl`, so the probe runs).
2. Sign in (`POST /v1/dev/sessions` into `$XDG_DATA_HOME/godot/app_userdata/Tabletop-dev/session.bin`, `settings.json` with
   `"rememberMe": true`, `"vSync": false`, a fixed `window`), then `TABLETOP_PERF_OUT=<dir>/run.csv TABLETOP_PERF_GAME=<clone>
   TABLETOP_PERF_SCRIPT=play TABLETOP_PERF_SECONDS=100 DISPLAY=:0 <out>/Tabletop.x86_64 --rendering-driver opengl3` on a fresh clone
   each run (the script moves and shoots). `TABLETOP_PERF_SHOTS=1` photographs each phase (each photo costs a 230 ms frame).
3. Read per phase: p50/p95/p99/max of `dt_ms`, frames over 33 ms, and for each spike `script_ms`, `cpu_render_ms` and the `probes`
   column. To find a cost, wrap suspects in `using var _ = PerfProbe.Time("name");` or `PerfProbe.Timed("name", () => …)` in the
   scratch copy only. Three runs a build, builds alternating, one Godot at a time.

Under WSLg Vulkan is llvmpipe; opengl3 runs on the host GPU through D3D12, so `gpu_ms` and a first-draw shader compile are not the
Windows Forward+ numbers. The main thread's C# time (`script_ms`, `probes`) is.

## Releases

`scripts/release-client` publishes a client only when its source fingerprint (`scripts/release-client source [<commit>]`)
differs from the published `releases/latest.json`'s `source` (deploy/README.md → Releases).

- Release when only the server changed: tag and run `scripts/release` as usual; it prints `client unchanged since <version>:
  not published` and deploys the servers and built-ins.
- Force a client publish: `scripts/release --force-client`, or `RELEASE_FORCE_CLIENT=1 scripts/release-client all <version> <out>`.
- Will this tag publish a client: compare `scripts/release-client source vX.Y.Z` with `source` in the published `latest.json`.
- Check a pack has no built-in files: `scripts/pck-files <export>/Tabletop.pck | grep content/builtin` lists `catalog.json` and `tables/` only.

## Adding an option

1. `ClientSettings`: an init property with its default; the DTO field (nullable, appended); `Load` (default when absent, clamped to its range),
   `Save` and `Equals`. `SettingsTests.An_old_file_loads_every_new_field_at_its_default` gains the field.
2. `OptionsModel.Rows`: a `Toggle`, `Choice` or `Slider` row in its category, with a one- or two-line description (what it changes, its
   default; fact only). `OptionsModelTests.Each_row_reads_its_default_and_writes_back_what_it_reads` covers the round trip.
3. Read it where it acts: through `Session.Settings` in the part that uses it (a `SettingsChanged` handler when it must apply at once);
   window, theme, buses, tooltip and frame counter in `Main.ApplyInterface`/`ApplyTheme`; the table's graphics in `GraphicsApplier`.
4. A new key is an `Intent` with a default in `KeyBindings` (its group and name too); every cap reads `Hotkeys.Bindings`, never a literal.
5. This file's `settings.json` list gains the field.

## Conventions and pitfalls

- `dotnet build client/Tabletop.csproj` compiles the Godot project from WSL; run it after editing a node file.
- `src/Core/` is compiled into `tests/Tabletop.Client.Tests` by `<Compile Include="../../client/src/Core/**/*.cs">`. A `using Godot` there breaks the tests; `check-client` fails on it. Core may reference only the three libs and the BCL.
- `check-client` also fails on a colour literal (`new Color(`, `Colors.`, `Color.FromHtml`, a target-typed `Modulate = new(`, and similar) under `src/Hud`, `src/Panels` or `src/Screens`: use `Ui` or a `Variation` (a `Flat` button sets `Variation.FlatButton`; the check does not test that). It also fails on: a physics body or collision shape in `client/scenes`; Godot physics types in `client/src`; a rules-engine type (`Tabletop.GameServer`, `IRulesEngine`, `CommandDispatcher`, `Legality`, and similar) in `client/src`.
- Every `ScrollContainer` sets `VerticalScrollMode = Reserve` (and `HorizontalScrollMode = Disabled`): content whose height depends on its width (wrapping labels, `HFlowContainer`) otherwise flips the bar on and off, and each flip queues another deferred re-layout in the same flush until Godot's message queue overflows ("Object was deleted while awaiting a callback", then a crash). `GameScreen.QueueLayout` also caps itself at four passes a frame and warns past that.
- A change to `CombatLog`, `RollEntry`, `LogSheet` or `UndoPlan` regenerates `viewer/tests/fixtures/combatlog.json` (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter CombatLogViewerFixture`) and is ported to `viewer/src/lib/play/` until `combatLog.agreement.test.ts` passes; a change to any other `src/Core/` file the viewer ports (`viewer/AGENTS.md` → Layout, `src/lib/play/`) is ported with its test.
- A change to `UnitActionsView` regenerates `viewer/tests/fixtures/unitActions.json` (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter UnitActionsViewerFixture`) and is ported to `viewer/src/lib/play/unitActionsView.ts` until `unitActions.agreement.test.ts` passes.
- Every outbound socket message is built by a Core function (the list under Layout, the outbound messages); a node only calls it. A new outbound message, or a new control that sends one, is not done until `CallsViewerFixtureTests` writes a case for it (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter CallsViewerFixture`, after the call logs: `tests/Tabletop.Viewer.Tests --filter CallLogFixture`) and `viewer/tests/calls.agreement.test.ts` passes. A difference is fixed in the browser, unless the case shows a Godot bug; then in both, with a test.
- No Godot physics; picking is ray versus AABB.
- Godot's import step wipes `client/.godot/mono/temp/bin/`. Build after an import; otherwise every script fails with "class could not be found". `./scripts/client` builds in WSL first.
- `Directory.Build.props` gives each OS its own `obj/Unix` or `obj/Windows_NT`; a shared `obj/` breaks restore. `TabletopBuildSlot` adds a suffix to `obj/` and `bin/` for the compose server containers; the client does not set it.
- The Godot editor runs on the Windows host, so the client reads and writes in `UserData.Dir` there: a release build uses `OS.GetUserDataDir()` (`%APPDATA%\Godot\app_userdata\Tabletop`), a development build the sibling `Tabletop-dev`, so a dev-stack JWT never reaches production or the reverse. Godot's `logs/` stay under `Tabletop` for both. A release build that finds server addresses in its `settings.json` clears `session.bin` and rewrites the settings without them. The files: `builtin.json` (`BuiltinSync`), `settings.json` (`ClientSettings`: `Animate`, `RememberMe`, `ManagementUrl`, `GameServerUrl`, `LogFilter`, `LogOpen`, `LogDetailed`, `Theme`, `CameraFollow`, `TurnBanner`, `RangeRings`, `ShowHitboxes`, `ShowTerrainHitboxes`, `MeasureMode`, `WebUrl`, `Sound`, `Volume` (the Master bus), `Display` (Windowed, Fullscreen = borderless, Exclusive), `Quality`, `RenderScale`, `VSync`, `FpsCap`, `Window`, `WoundNumbers`, `PanSpeed`, `OrbitSpeed`, `ZoomSpeed`, `EdgeScroll`, `InvertOrbit`, `InvertZoom`, `KeyOverrides` (saved as `keys`), `ShowFps`, `EffectsVolume`, `MuteInBackground`, `UiScale`, `TooltipMs`, `ToastSeconds`, `ColourBlind`, `TextSize`, `ReduceMotion`; each nullable in the DTO, so an older file loads with defaults), `session.bin` (the remembered JWT, `SessionStore`) and `cache/` (`AssetCache`). Signing in a headless dev run without a password: write the JWT from `POST /v1/dev/sessions` to `Tabletop-dev/session.bin` (on Linux `~/.local/share/godot/app_userdata/Tabletop-dev/`). Settings are presentation only and never reach the server.
- A development build's default URLs use `127.0.0.1`, not `localhost`: Windows tries `::1` first, which does not reach WSL, and .NET waits 21 s before falling back.
- `Session` raises events on the main thread only through `IDispatcher`; tests use `ImmediateDispatcher`.
- `SessionStore.Read` returns null for anything that is not three non-empty dot-separated segments, so a corrupt file never reaches an Authorization header.
- `.tscn`, `.tres`, `.godot` and `.import` files are owned by the editor: hand-edit only when necessary, never reformat. Scenes are written minimal and owned by the editor afterwards.
- No scene may contain a physics body; dev tooling stays out of `client/`, since the editor scans everything under the project root.
- C# only, no GDScript. One world unit is one inch.
- `net10.0` runs under Godot's `net8.0` host because `GodotPlugins.runtimeconfig.json` sets `rollForward: LatestMajor`. If a Godot upgrade breaks C# loading, drop the TFM to `net8.0` first.
