Sources: `GF - Advanced_Rules_v3_5_1.pdf` (71 pages) and `GF_-_Advanced_Rulebook_v3_6_0.pdf` (74 pages), both in
`/mnt/c/Users/clays/Downloads/`, extracted page by page and compared word by word; the deployment diagrams (images) were
measured on the 6" grid 3.6.0 draws. Army books: Army Forge's live index and books (fetched 2026-10-29, all 49 at
`versionString` 3.6.0) against the 3.5.x dump in `.superpowers/armyforge/`. How both rule sets run side by side is
`2026-10-29-rule-set-versions-design.md`. Optional modules, army books, wording-only changes, version naming and rulings
are in `2026-10-29-gf-3-6-0-rules-diff-modules.md`.

Each change gives the 3.5.1 and 3.6.0 text with pages, the effect at the table, where the engine has the 3.5.1 behaviour,
and a mark: **engine** (code change), **data** (property set, catalog or text only), **no impact**, **new rule**.

## Core rules (pp.4–12)

### C1. Who can strike in melee — engine

- 3.5.1 p.9: *"All models that are within 2” horizontally and 4” vertically of an enemy model from the target unit, may
  attack it."*
- 3.6.0 p.9: *"All models that are within 3” of an enemy model from the target unit (horizontally or vertically), may
  attack it."*
- Table: reach is 3" in any direction from base to base, so a second rank 2–3" back now strikes, and a model on a floor 3–4"
  above no longer does.
- Engine: `GfNames.MeleeHorizontal = 2, MeleeVertical = 4`; `GfMelee.InReach`, `GfAttack` (melee eligibility, line ~351).
  Suite: melee games in `sim/Suite/SuiteCatalog.Core.Melee.cs`, `SuiteCatalog.Core.Elevation.cs`. Client/viewer reach
  rings, if drawn from these numbers, read the server's. Size **S**.

### C2. Fatigue — engine

- 3.5.1 p.9: *"After attacking in melee for the first time during a round, either by charging or by striking back, units
  only hit on unmodified rolls of 6 in melee until the end of that round."*
- 3.6.0 p.9: *"After a melee where they attacked, units hit on unmodified rolls of 6 in melee until the end of that round,
  and those hits don’t count as rolls of 6 for special rules."*
- Table: a fatigued unit's 6s no longer trigger Rending, Furious, Surge, Bane-style re-rolls or any army rule keyed on a 6
  to hit. A Shaken unit striking back "counting as Fatigued" (p.10, unchanged) gets the same.
- Engine: `GfRolls.Fatigued`, `GfRolls` hit plan (`RequiredRaw = 6`); 6-triggers come from `RollEffects.Triggers` and
  `Die.Triggered`, which today fire on a fatigued 6. Suite: fatigue checks in `SuiteCatalog.Special.Melee.cs`,
  `SuiteCatalog.Special.Log.cs`. Size **S**.

### C3. Melee morale: who lost — no impact (one edge)

- 3.5.1 p.10: *"must compare the number of wounds each unit caused instead. The unit with the lowest total loses"*.
- 3.6.0 p.10: *"must compare the number of wounds each unit took during this activation instead. The unit with the highest
  total loses"*. Melee resolution (p.10, first column) still sums *"wounds that each unit caused"*, unchanged.
- Table: the same between two units. It differs only where a unit takes wounds in the activation from something other than
  its opponent (a Dangerous Terrain Test on the charge move): 3.6.0 counts those against it.
- Engine: `GfMelee`'s resolution step (`charger_wounds`, `defender_wounds`, `loser`) sums the wounds caused in the melee
  frame, so the charge's dangerous-terrain wounds are not counted; 3.6.0 counts them. Size **S**.

### C4. Dangerous terrain — engine

- 3.5.1 p.11: *"If a model moves in or through dangerous terrain, or is activated in it, then it must take a dangerous
  terrain test. To take a dangerous terrain test, roll one die (or as many dice as the model’s Tough value), and if the
  result is 1, then the unit takes one automatic wound."*
- 3.6.0 p.12: *"If any model in a unit moves into or through Dangerous terrain, or activates in it, then the entire unit
  must take a Dangerous Terrain Test. To take a Dangerous Terrain Test, roll as many dice as the number of wounds it would
  take to fully destroy the unit, and for each result is 1 the unit takes one wound."*
- Table: one model touching the hazard makes the whole unit roll, one die per remaining wound of the unit (models ×
  wounds left). A 10-model squad with one model crossing rolls 10 dice, not 1.
- Engine: `GfMoves.DangerousTerrain()` (`DangerousTestStep`, `DangerousDealStep`), `GfMoves.DangerousDice` (sum of Tough
  per testing model), `TestedThisActivation` / `dangerous_tested_<model>` (once per model per activation; becomes once per
  unit). Transport destroyed (`transport-destroyed`) and every rule that says "take a Dangerous Terrain Test" (army rules,
  spells, Banner of Eternal Flame interplay) use the same test. Suite: `SuiteCatalog.Core.Ruins.cs`,
  `SuiteCatalog.Core.Actions.cs`, `SuiteCatalog.Special.Melee.cs`, `SuiteCatalog.Army.Batch2*.cs`, `SuiteCatalog.Spells.cs`.
  Size **M**.

### C5. Terrain types: Sight Blocking, Dense, Unstable, Steep, Climbable — engine + data

- 3.5.1 pp.11–12 types: open, impassable, blocking, cover, difficult, dangerous, elevated; p.12's list: *"Forests -
  Difficult + Cover + Units can see into and out of forests, but not through them • Hills - Cover + Difficult when moving
  up + Units on top may ignore one unit/terrain for line of sight • … • Rivers - Dangerous when using rush/charge • … •
  Ruins - Cover + Dangerous when using rush/charge"*.
- 3.6.0 pp.11–12 types: open, impassable, **sight blocking** (blocking renamed), cover, difficult, dangerous, and new:
  - *"DENSE TERRAIN … Units may draw line of sight into and out of dense terrain, but not through it to targets on the other
    side."*
  - *"UNSTABLE TERRAIN … If any model in a unit moves over 6” when moving into or through unstable terrain, then it counts
    as Dangerous terrain."*
  - *"STEEP TERRAIN … Units moving onto steep terrain count it as being in Difficult terrain, but units moving off it count
    it as open terrain."*
  - *"CLIMBABLE TERRAIN"* is 3.5.1's elevated terrain, text unchanged (over 3" impassable, up to 3" climbable, 3"
    coherency across elevations, up to 1" ignored).
  - p.11 list: *"Forests - Difficult + Cover + Dense • Hills - Cover + Steep • … • Rivers - Difficult (if shallow) / Unstable
    (if deep) • Rubble - Difficult • Ruins - Cover + Unstable • Swamps - Difficult • Walls - Climbable"*.
- Table: the rush/charge trigger becomes a distance trigger (over 6" while entering or crossing): an Advance with Fast
  (8") through ruins now tests, a 5" charge into ruins does not. Hills lose "ignore one unit/terrain for line of sight".
  Rivers stop being dangerous unless deep.
- Engine: `TerrainDeclarations` (libs/Tabletop.Geometry/Volumes.cs: `SeeInAndOut` = Dense, `DangerousOnRushCharge`),
  `BuiltinTerrain.DeclarationNames` (`see_in_and_out`, `dangerous_on_rush_charge`), `GfMoves.DangerousFor(terrain,
  rushOrCharge)`; persistence `RowMapping`; `client/content/builtin/catalog.json` declarations; `TerrainLabel` and the
  viewer's terrain text show declaration names. Steep is new (`Difficult` on entry only, read from the path's direction).
  The hill sight clause and steep-hill's "Difficult … moving up" were never built; they are `notes` on `hill`, `large-hill`, `steep-hill` in the catalog. Suite: `SuiteCatalog.Core.Ruins.cs`, `SuiteCatalog.Core.Paths.cs`. Size **M**.

### C6. Force organisation — new rule (optional)

- 3.6.0 p.6 adds *"• Only 1 model or Tough per 20pts"*; example *"max. 100 models or Tough in total"*.
- Table: an army-building cap counting each model, or each point of Tough, against 1 per 20 pts. Optional (p.6
  "Optionally … force organisation rules").
- Engine: none; force organisation is not built (`ArmyLimits` holds size limits, not p.6's). Not raised.

### C7. Placing objectives — no impact

- 3.5.1 p.6: *"The players roll-off and the winner picks who places the first objective marker."* 3.6.0 p.6: *"The players
  roll-off to see who goes first"*.
- Engine: markers are placed in setup by the creator (`DraftEditor`); no roll-off is modelled.

### C8. Clarifications already matching — no impact

- p.8 and p.9 Remove Casualties add *"If all models are removed, then the unit counts as destroyed."*
- p.10 Rout adds *"and counts as destroyed"*; consolidation reads *"move back and separate by 1” (if possible), to show
  that they are not in melee anymore"*.
- p.6 adds *"Once all units have been deployed, the game begins with the first round."*

## Special rules (pp.13–15)

Rule text lives in `server/game/Content/grimdark-future-core.properties.json` (`ruleText`, effect rows, `aggregation`);
behaviour named in C# is in `server/game/Rules/GrimdarkFuture/`. Every changed rule needs its `ruleText` replaced in the
3.6.0 set whatever its mark.

### S1. Aircraft — data + engine

- 3.5.1 p.13: *"can’t be charged, and units targeting them get -12” to their range."*
- 3.6.0 p.13: *"can’t be moved in contact with or charged, and units targeting them get -12” range and -1 to hit rolls."*
- Table: shooting at an Aircraft is also -1 to hit; nothing may end a move touching one.
- Engine: the core entry's `modify_stat` -12 on range gains a -1 `modify_roll` on hit (`LivePropertiesTests`,
  `RollEffectsTests` pin the 3.5.1 reading). Charge targets already exclude Aircraft (`GfMelee` ~136); a non-charge move
  into contact is already a `move_separation` breach. Suite: `SuiteCatalog.Special.Shooting.cs`. Size **S**.

### S2. Artillery — data + engine

- 3.5.1 p.13: *"May only use Hold actions. When this model shoots at enemies over 9" away, it gets +1 to hit rolls. When
  enemy units shoot at this model from over 9" away, they get -2 to hit rolls."*
- 3.6.0 p.13: *"When this model uses Hold actions and shoots at enemies over 12” away, it gets +1 to hit rolls. If most
  models in this unit have this rule, as long as they haven't moved during this round, enemy units shooting at them from
  over 12” away get -1 to hit rolls."*
- Table: Artillery may move; its +1 needs a Hold and a target over 12"; the defence is -1, over 12", only while the unit
  has not moved this round.
- Engine: `GfRules.Scheduling` (`ArtilleryNote` "may only use Hold actions (p.13)", Hold-only legal set); core entry
  effects and `aggregation: all` → `majority`; `GfNames.MovedThisRound` is the condition. Suite:
  `SuiteCatalog.Special.Shooting.cs`, `SuiteCatalog.Army.Batch4.cs`, `Batch8.cs`. Size **S**.

### S3. Assault — new rule

- 3.6.0 p.13: *"Counts as both a ranged weapon and a melee weapon."* (The Assault extra action, 3.5.1 p.30, is gone.)
- Table: one weapon profile shoots and strikes.
- Engine: weapons are ranged or melee by range (`GfGroups`, `GfMelee.MeleeWeapons`). An Assault weapon has a range and
  must also be read as melee. 3.6.0 books use it. Size **S**.

### S4. Caster(X) — engine

- 3.5.1 p.13: *"At any point before attacking, spend … Roll one die, on 4+ resolve the effect on a target in line of
  sight. Models within 18” in line of sight of the caster’s unit may spend any number of spell tokens"*.
- 3.6.0 p.13: *"Once per activation, before attacking, spend … Pick a target and roll one die, and on 4+ resolve the
  spell’s effect. Models within 18” of the Caster may spend any number of spell tokens"*.
- Table: casting happens once per activation (one cast window, still several spells, one try each); the core rule no
  longer requires line of sight to the target (a spell's own text still limits it); helpers need only be within 18" of
  the Caster model, no line of sight, measured to the Caster rather than its unit.
- Engine: `GfCasting` (`EligibleSpenders` ~line 88–93: `CastRange` and `CanSee`; target filter ~112–121:
  `sight.Value.CanSee(casterModel, m)` unless the spell's targeting sets `LineOfSight: false`), `GfHooks` (when the cast
  window opens; "at any point before attacking" lets a moving caster stop to cast, `DecisionView.StopLabel`).
  Decision 2 (`OneTryPerSpellScope = activation`) stands. Suite: `SuiteCatalog.Special.Casting.cs`, `SpellGames.cs`,
  `SuiteCatalog.Spells.cs`. Size **M**.

### S5. Counter — engine

- 3.5.1 p.13: *"Strikes first with this weapon when charged, and the charging unit gets -1 total Impact rolls per model
  with Counter."*
- 3.6.0 p.13: *"May strike first with this weapon when charged, unless this unit is Fatigued."*
- Table: striking first is the defender's choice and is lost once fatigued; Counter no longer cancels Impact dice.
- Engine: `GfMelee.CounterStep` (always strikes first), `ImpactStep` (subtracts one die per Counter model, summary line
  ~233). Suite: `SuiteCatalog.Special.Melee.cs`, `SuiteCatalog.Army.cs`. Size **S** (a yes/no Ask to the defender).

### S6. Cumbersome — new rule

- 3.6.0 p.14: *"May only use Hold or Advance actions, but can’t shoot when moving."* In 18 of 49 3.6.0 books.
- Engine: an action filter beside Immobile in `GfRules.Scheduling` (activation legal set) plus the advance sequence's
  shooting. Size **S**.

### S7. Fear(X) — no impact

- 3.5.1 p.13: *"This model counts as having dealt +X wounds when checking who won melee."* 3.6.0 p.14: *"When in melee
  with this model, enemies count as having taken +X wounds when checking who won."* Same result under C3's comparison.

### S8. Fearless, Regeneration, Stealth: "all" → "most" — data

- 3.5.1: *"a unit where all models have this rule"* (Fearless p.13, Regeneration p.14), *"units where all models"*
  (Stealth p.14). 3.6.0: *"most models"* in all three.
- Table: a Hero without the rule in a unit that has it no longer switches the rule off.
- Engine: core entries' `aggregation: "all"` → `"majority"` (`Aggregation.Majority` exists, `LiveProperties` ~254,
  `Lookup` ~58). Decision 4 in `docs/design/interpreter/decisions.md` records `all` from the 3.5.1 text; for 3.6.0 it
  reads `majority`. Tests pinning `all`: `GfDealWoundsTests`, `LivePropertiesTests`, `GfAttack.cs` comment ~183.
  Size **S**.

### S9. Flying — engine

- 3.5.1 p.13: *"may move through units and terrain, and ignore terrain effects whilst moving."*
- 3.6.0 p.14: *"May move through units and terrain, and ignores the effects of Difficult and Dangerous terrain."*
- Table: Flying is named against Difficult and Dangerous only (Steep's difficulty is Difficult; Unstable resolves as
  Dangerous); the clause is no longer limited to moving, so a Flying unit activating in Dangerous terrain does not test.
- Engine: `GfMoves.TerrainFor` (Flying/Strider/Banner of Eternal Flame), the "activated in it" test in
  `GfMoves.DangerousTerrain`. Size **S**.

### S10. Hero — engine

- 3.5.1 p.14: *"The hero may take morale tests on behalf of the unit, but must use the unit’s Defense until all other
  models have been killed."*
- 3.6.0 p.14: *"… but must use the unit’s Defense until all other models have been killed. The Hero’s unit, and units
  within 6” of friendly Heroes with Tough(9) or higher, may use the Hero’s Quality for Morale Tests as long as the Hero
  isn’t Shaken."*
- Table: a big Hero (Tough(9)+) lends its Quality to every friendly unit within 6" for Morale Tests, unless it is Shaken.
  Joined Heroes behave as before.
- Engine: joined Hero's Quality for morale is decision 13 (better of the two while the hero lives) in `GfRolls`/
  `StatReader`; the 6" aura is new in `GfMorale` (morale test threshold). Suite: new game in `SuiteCatalog.Special.Melee.cs`.
  Size **M**.

### S11. Impact(X) — engine

- 3.5.1 p.14: *"Roll X dice when attacking after charging, unless fatigued. For each 2+ the target takes one hit."*
- 3.6.0 p.14: *"When charging, before either unit attacks, roll X dice, unless this unit is Fatigued. For each 2+ the target
  takes 1 hit."*
- Table: Impact resolves before Counter strikes; no Counter reduction (S5).
- Engine: `GfMelee.Melee()` sequence order `MeleeStartStep, CounterStep, ImpactStep, …` becomes Impact before Counter;
  `ImpactStep` drops the Counter subtraction. Heavy Impact (`GfNames.HeavyImpact`) rides the same step. Suite:
  `SuiteCatalog.Special.Melee.cs`, `SuiteCatalog.Special.Log.cs`, `SuiteCatalog.Army.Batch8.cs`. Size **S**.

### S12. Indirect — data + engine

- 3.5.1 p.14: *"Gets -1 to hit rolls when shooting after moving. May target enemies that are not in line of sight as if in
  line of sight, and ignores cover from sight obstructions."*
- 3.6.0 p.14: *"When using Hold actions and shooting, may target enemies that are not in line of sight as if in line of
  sight, and ignores cover from Sight Blockers."*
- Table: no -1 after moving; after moving it shoots normally (needs line of sight, cover applies).
- Engine: the core entry's -1 row goes; `GfAttack` sight and cover reads of Indirect (`GfNames.Indirect`) gain the
  Hold condition. Suite: `SuiteCatalog.Special.Shooting.cs`, `SuiteCatalog.Army.Auras.cs`, `Batch8.cs`. Size **S**.

### S13. Scout — engine

- 3.5.1 p.14: *"may be deployed anywhere fully within 12” of their deployment zone."*
- 3.6.0 p.15: *"may be deployed anywhere fully within 9” of their deployment zone, over 9” away from non-Scout enemy
  units."*
- Engine: `GfNames.ScoutReach = 12`, `GrimdarkFutureRules.ZoneBreach` (`deploy_zone`, GfRules.Deployment ~51); the 9"
  enemy clearance is new (a placement breach like `AmbushBreach`'s `ambush_distance`). Army rules that count as Scout
  (Infiltrate etc.) follow. Suite: `SuiteCatalog.Special.Deployment.cs`, `SuiteCatalog.Core.Mission.cs`. Size **S**.

### S14. Shred, Spell Amplifier — new core rules

- 3.6.0 p.15 Shred: *"For each unmodified result of 1 to block hits, this weapon deals 1 extra wound."* Already an army
  rule (`grimdark-future-army-rules.part.json`, same effect); it moves into the core set. **data**.
- 3.6.0 p.15 Spell Amplifier: *"Gets +1 to casting rolls."* A `modify_roll` on casting. **data**, size **S**.

### S15. Transport(X) — engine (small)

- 3.6.0 p.15 adds *"friendly"*, *"getting in contact to enter"*, and *"If the Transport is unreachable (for example because
  it’s flying), then units can’t embark in it."*
- Engine: friendly only is decision 9 already. Embarking into an Aircraft transport (`GfMoves.ContainersInReach`) must be
  refused. Size **S**.

### S16. Unstoppable — data

- 3.5.1 p.15: *"ignores all negative modifiers to this weapon."* 3.6.0 p.15: *"ignores all negative modifiers to this
  weapon which are not from this model's special rules."*
- Engine: the core entry's `to_hit_penalties` suppression gains an exception for the holder's own rows. Suite:
  `SuiteCatalog.Special.Shooting.cs`, `SuiteCatalog.Army.Grants.cs`. Size **S**.

### S17. Wording only, same behaviour — no impact

Ambush ("Ambush units"), Bane (comma), Furious ("in melee" dropped; charging implies melee), Relentless, Surge ("For each
unmodified result of 6", same per-die reading), Rending (book text "for each"), Strider ("when moving" dropped; Difficult
only), Takedown ("for this weapon's attacks", decision 7 already per weapon), Thrust, Tough (capitals). AP, Blast,
Deadly, Fast, Immobile, Limited, Reliable, Slow unchanged.
