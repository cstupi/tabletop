## Thumbnails

The spec asks for `GET /v1/assets/{id}/thumbnail`, rendered once at upload from the GLB the browser already previews. One request per
tile would cost a library of 200 models 200 requests (and the per-account rate limit), so the thumbnail's presigned URL rides on the
lists instead, and the write is its own endpoint:

- `PUT /v1/assets/{id}/thumbnail` (owner, uploaded mesh asset): the body is a PNG or WebP of at most 256 KiB and 512 × 512, checked with
  `ImageHeader.Read`; it is stored at `thumbs/{assetId}/{sha256}` (`IBlobStore.ThumbnailKey`), a new key per picture, and the asset's `thumbnail_key` set
  to it; the key it replaces goes unless a copy still names it. 204.
- Migration `030_asset_thumbnail.sql`: `asset.thumbnail_key text` (null: none), indexed where set.
- `AssetDto`, `OfferAssetDto` (and `SharedAssetDto`) gain `thumbnail` (presigned GET, 60 min) when the key is set, filled by the list
  endpoints (`GET /v1/assets`, `/v1/offers/received`, `/v1/offers/sent`, `/v1/shared/{username}`); the key itself never leaves the server.
- A copy (offer Accept, Shared-folder copy, `AssetCopies.Copy`) takes the source's `thumbnail_key`, so it names the sharer's object as its
  blob row names the sharer's file. `Unreferenced` counts a key named by `asset.thumbnail_key` as referenced; deleting an asset deletes
  its thumbnail object when nothing names it; `AccountRepository.BlobKeys` adds the account's thumbnail keys.
- The browser renders the thumbnail (`web/src/lib/mesh/thumbnail.ts`, three.js offscreen, 256 × 256 WebP, PNG where WebP encoding is
  missing) after a mesh upload confirms, and on the asset page when the asset has none or its scale or orientation is saved. A failure
  leaves the asset without one. Assets without a thumbnail (the starter miniatures, earlier uploads) draw the kind icon.

## Tasks

1. Management: migration, repository members (`SetThumbnail`, thumbnail key on the DTO rows, copies, `Unreferenced`, `BlobKeys`), the
   in-memory fakes, the endpoint and the list presigns; contract and endpoint tests first. `docs/schema.md`, `server/management/AGENTS.md`.
2. Web shared vocabulary: `app.css` `.card`, `.tile`, `.chip`, `.chip.status-*`, `.quiet-band`, `.pips`, `kbd`; icons `mesh`, `menu`,
   `offer`, `player`, `ready`, `warning`, `copy`, `remove`, `link`, `quality`, `defense`, `base`, `height`, `account` in `icons.ts`.
3. Shell: header holds the tabs and one `▾` menu on the account name (Account, the two theme swatch tiles, Log out).
4. Sign-in: the two explanation sentences go. Account: the delete panel's text is the spec's one line.
5. Armies: one import row (the paragraph as the field's tooltip); a card per army (system icon with the system name as tooltip, edition
   chip, units and models, mesh pips `meshes N of M`, Open, `▸` menu with Re-import and Delete). `ArmySummary` lacks slot meshes: the
   card counts them from the army, fetched per card (`api.armies.get`), as the army page does.
6. Army page: heading with an edit icon (rename in place), facts line with Army Forge ↗ and the meshes count, the page's mesh folder
   once, a card per unit (neutral band, name, count, Quality and Defense badges), a slot row per distinct slot group: thumbnail, name,
   mesh picker, base, height; `▸ per model` opens a row per model when the models share a group.
7. Library: tiles draw the thumbnail (else the kind icon), the name, the base icon and size; the multi-select sentence goes; tree tools
   get worded tooltips and Delete the danger colour; the usage line becomes a bar.
8. Upload: unit and up-axis choices as tiles; the stage list as a vertical stepper with the `ready` icon on done stages; the thumbnail
   rendered and sent after confirm.
9. Offers: a card per offer (sender's `player` icon and name, asset thumbnails, Accept with the folder picker, Decline, Block in `▸`);
   Sent as cards with a status chip and Withdraw on a waiting one; empty state is the `offer` icon and `No offers`. Shared by players
   keeps its behaviour and takes the thumbnails and cards.
10. Download: the detected platform's build as the primary tile, others as flat tiles, first-run steps numbered with the `warning`
    icon on the unsigned-build step.
11. `web/AGENTS.md`, `docs/design/web-app/design.md` to the current behaviour.
