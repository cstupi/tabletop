# viewer

A static web app that draws a `sim/` recording or a game's log top-down on a 2D canvas. Plain Vite + Svelte 5 + Vitest, its own `package.json`. Two builds: the developer viewer (`npm run dev`, `npm run build`) and the hosted build (`npm run build:hosted`), which production serves at `/viewer/` on the website's origin as the browser play and replay app, open to every signed-in player.

## How it works

- Every feed produces `FeedState` in the recording's own schema, so the renderer cannot tell the sources apart.
- Recording feed: a file or URL read by `parseRecording`; needs no server.
- Live feed (the Watch tab): the source picker lists `GET /v1/games` with the website's session (the viewer is served under `/viewer/` on the website's origin in development too, `web/vite.config.ts` proxying it), and a click opens `liveFeed.ts` on `/ws?watch=1` (`VITE_GAME_SOCKET`, default `ws://127.0.0.1:5200/ws`). An admin watches any game; anyone else only their own.
- Live frames come from `Applier` (port of `Tabletop.Protocol.EventApplier`) and `FrameProjector` (port of `Tabletop.Sim.Recording.FrameProjector`); `lineOf` ports `Tabletop.Sim.Recording.LogLines`.
- A picker lists every army as `armyLabel` (`name (edition)`); an army of another edition than the game's is disabled with the reason "3.5 list" or "3.6 list" (`lobbyView.ts`, a port of `LobbyView`; its `EDITION_OF` copies `RuleSets.EditionOf`), the army's own field; the game server refuses it either way. A lobby edition change arrives as `rules_options` (options, zones, terrain words), which `ConnectionState` applies.
- Zone legs come from Welcome: `ConnectionState.zones` is `Welcome.zones`, and setup, play and replay pass it to `sceneOfTable`/`sceneOfPlay`, which hand it to `Geometry.zonePolygons` (`zoneContains`, `zoneHoldsBase` take it too; absent is the geometry's default). The live feed carries it as `RecordingMeta.zones`. Nothing in the viewer names an edition.
- The marker range comes from Welcome: `ConnectionState.markerRange` is `Welcome.markerRange` (or `rules_options`'), passed to `sceneOfTable`/`sceneOfPlay` as each `MarkerShape.reach`, which `draw.ts` strokes as a dashed ring about the marker's centre.
- Terrain words come from Welcome: `ConnectionState.terrainWords` is `Welcome.terrainWords`, passed to `terrainLabelOf`, `terrainHoverText`, `terrainCardOf`, `terrainGroups`/`terrainSummary` and `TerrainCard.svelte`, which show `declarationWords(words)` (the server's word, else `DECLARATION_WORDS`); the live feed carries them as `RecordingMeta.terrainWords`. `contactCheck.move` passes `MoveRegion.steepVolumeIds` as the contact terms' `steep`.
- The board is a grid in inches in the theme's `--board-*` colours (`Board.svelte` rereads them when `<html data-theme>` changes): models as bases or circles in their team's colour with a facing tick, terrain as a soft fill and outline by kind, zones as tinted bands, objectives as ringed discs; terrain and marker names only from 18 px per inch or when selected, never ids or declarations.
- Replay (`src/lib/replay/`): Godot's `ReplayTimeline`, `ReplayClock` and `ReplayBar` ported; position counts events applied, stops by step, action, turn and round; Play steps every 1.5 s over the speed, stops at the end of an ended game and starts again from 0 there. The page loads the geometry for zones, so it stays out of the playback roots `geometry.lazy.test.ts` checks.
- The Tests page (header tab) drives the runner service (`sim serve`): `/suite` and `/runs` are proxied to `TABLETOP_SUITE_PROXY_TARGET` (default `http://localhost:5180`; compose `http://sim-runner:5180`). Watch loads a kept recording; Open live asks the runner for a spectator session (`POST /runs/{id}/games/{game}/spectate`) and opens the live feed on that kept socket game. The page groups the games, runs a selection with Keep and a driver, lists each result
  as it arrives (a game pinned to an engine defect shows failures prefixed `known defect <id>: `) and the coverage table at the end.
- The Tests page filters by edition: a row of rule-set names above the groups selects or deselects every game of that set (`editionsOf`, `toggleEdition`); games and coverage rows show the set name, never the rules id (each game and coverage entry carries its set's `ruleSet` name from the server).
- Hosted build (Vite mode `hosted`, base `/viewer/`): `web/Dockerfile` builds it into the web image at `/srv/viewer`; `web/Caddyfile` serves it with its own CSP header. It has no login form: it reads the website's session from `localStorage` `tabletop.session` (`{ sessionJwt, account }`, written by `web/src/lib/session/session.svelte.ts`), uses the stored JWT until 60 s before its `exp`, then refreshes it and writes the new JWT back. Signed out (nothing stored, or a refresh refused with a 4xx but 429) shows a sign-in link to `/login?next=/viewer/`; every signed-in account opens it; the `admin` role adds the Watch tab. The socket is `wss://<page host>/ws`. No Tests tab (`config.runner` is false). The Games panel opens loaded; `GET /v1/games` lists ended games too, and the live feed replays a game's log from the start.
- Geometry in the browser (`src/lib/geometry/`): the first `loadGeometry()` fetches the .NET runtime and `Tabletop.Geometry.Wasm` from `${BASE_URL}geometry/_framework/` (2.4 MB brotli compiled ahead of time, as the web image builds it; 1.7 MB on the interpreter, from a host without the `wasm-tools` workload; Caddy serves the precompressed files), once per page; playback never calls it, which `tests/geometry.lazy.test.ts` checks. Each call is a JSON request to one `libs/Tabletop.Geometry.Wasm` facade method and a JSON answer, synchronous once loaded; held pieces are always lifted (the browser drops them). `tests/geometry.agreement.test.ts` replays `tests/fixtures/geometry.cases.json` through the WebAssembly.
- Playback (`PlaybackView`, a `Feed`) sends no command; the server refuses a watcher anything that changes the game (`refused`, reason `watcher`); replays open on `?watch=1`. Play uses `GameConnection` (`connectGame`), a participant socket: it sends edits and commands and settles each on its `Refused` or the next frame of its kind (a `game` frame for the lobby edits in `LOBBY_EDITS`, a `board` frame for setup edits), queues 16 while reconnecting, backs off 1/2/5/10 s, sends `Reauth` every 60 s and resyncs once per log position. The browser judges nothing: it mirrors limits only to explain before the server refuses, and every lobby and setup control sends one edit Godot sends.
- The game page: `GamePage` shows a header strip, then `LobbyPage` in the lobby (a head with the creator's Start setup and Still to do, the team columns beside the Game settings panel), `SetupPage` in setup (the tools sidebar, Still to do and the compact team columns first, the draft as a board scene with solid drags landed by `Geometry.landPiece` and turns by `turnPiece`, the selected piece's card on the right; End setup in the strip), and `PlayPage` (the projection as a board scene, the header, roster and roll-off banner, the decision box, the info column, the Game over modal, the menus) from playing. Every answer is an `AnswerAsk` and every hand action one ordinary command through `sendCommand`; a refusal shows Godot's text (`refusalText`). The board's interaction in play: a click selects a unit or answers the open Ask, a drag moves a model or marker (`PlayDrags`): a plain drag on a picked model holds the picks, on any other model its whole unit (clearing the picks); Shift+click toggles a model of my team in the picks, Shift+drag from one of my models holds it alone (`pointer.ts` offers a press on a hit to the drag before the box; `PlayDrags.onDragStart` takes a Shift press only for `shiftPress`'s `holdOne`) and Shift+drag from anywhere else boxes them (`modelPicks.ts`, the selection's model ids; a plain click on the table, a new Ask or Esc clears them), a right click opens `PieceMenu` (Shift: the unit's menu; a header team name and a roster row open theirs), L held draws the sight check, V toggles range rings. Undo is predicted locally (`UndoPrediction`) until the server's `undone` arrives. The play settings (muted windows, range rings, log open, filter and Detailed) are in `localStorage` `tabletop.play`. The box answers with `AnswerAsk` for the team the Ask was rendered for; a `Refused` for its last command, even one that arrives after another player's frame settled the send, shows `The server refused: <detail>` over the same Ask until a ghost is dragged, and the gate line that repeats it is hidden. The box takes its full height up to 70% of the column and scrolls as a whole past that; the header keeps three single-line rows, so the board never refits as its lines change. Geometry loads only when the page enters setup. A `ReplaceDraft` (layout, random table) makes the server give the pieces and markers new ids, so a selection does not survive it.
- Management calls the viewer makes: the auth endpoints, `/v1/account`, games, `/v1/properties`, `/v1/armies`, `/v1/assets?kind=terrain` and `/v1/assets/{id}/volumes`, `/v1/layouts` (list, get, save, delete), `/v1/layouts/builtin`, `/v1/layouts/random`, `/v1/builtin`. `GET /v1/builtin` answers 404 when nothing is published; the setup page then uses `client/content/builtin/catalog.json`, bundled through the `@builtin-catalog` alias (the web image copies it in).

## Commands

- `docker compose up -d` runs the dev server as the `viewer` service on `http://127.0.0.1:5174`, `/v1` proxied to
  `http://management:5100`, `VITE_GAME_SOCKET=ws://127.0.0.1:5200/ws`. It shares `viewer/node_modules` with the host and
  runs `npm ci` on start when `package-lock.json` differs from the hash in `node_modules/.tabletop-lock.sha256`.
- `./scripts/geometry-wasm` (needs the .NET SDK) before `npm test`, `npm run dev` and a build: it publishes the runtime into `public/geometry/`. `docker compose up -d geometry-wasm` does the same for the dev stack after a Geometry change.
- `cd viewer && npm install`
- `cd viewer && npm run dev` (after `docker compose stop viewer`): `:5174`, `/v1` proxied to `TABLETOP_API_PROXY_TARGET`,
  default `http://localhost:5100`.
- `cd viewer && npm test`: Vitest (`tests/**/*.test.ts`).
- `cd viewer && npm run check`: `svelte-check`.
- `cd viewer && npm run test:e2e` (stack up, `./scripts/geometry-wasm` done): `tests/e2e/setup.e2e.test.ts` takes a game from lobby to playing over HTTP and the socket through the same modules the pages use, `ambush.e2e.test.ts` sets a unit aside from the roster menu, plays to the round boundary and places the Ambusher through the decision box (refused within 9" of an enemy, accepted over 9"; two accounts, then one account holding both teams), and `play.e2e.test.ts` answers a deploy pick through the decision box on real connections, checks a strict refusal, drags units into place, and plays a game from lobby through deployment and round 1 (`driver.ts`: one seat's `step` through the page's own modules; `harness.ts`: sessions, army import, `sweep`, `playingGame` and `oneAccountGame` with their `cleanup`); skipped without `TABLETOP_E2E=1`. `TABLETOP_E2E_MANAGEMENT` overrides management's address (default `http://127.0.0.1:5100`; the website's `http://127.0.0.1:5173` proxies `/v1` too). The suites sign in fixed accounts (`viewer-e2e-<label>-<seat>`), sweep what those accounts made before they start, and delete every game, army and layout they make in `finally`: nothing they create stays in the Open games list.
- `cd viewer && npm run build` (developer) and `npm run build:hosted` (production, `dist/` with base `/viewer/`).
- Regenerate types: `TABLETOP_WRITE_GENERATED=1 dotnet test tests/Tabletop.Viewer.Tests`.
- Regenerate fixtures: `TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Viewer.Tests`.
- Record a run: `dotnet run --project sim -- skirmish --seeds 1..20` (files in `./recordings`).

## Conventions and pitfalls

- No SvelteKit and no code shared with `web/` (the hosted build shares only the `tabletop.session` storage entry).
- `src/lib/protocol/*.generated.ts` are never hand-edited. A plain `dotnet test` fails when they are stale.
- A change to `libs/Tabletop.Geometry` or the facade reruns `TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Geometry.Wasm.Tests` (writes `tests/fixtures/geometry.cases.json`) and `./scripts/geometry-wasm`. The hosted CSP's `'wasm-unsafe-eval'` (`web/Caddyfile`) lets the runtime start.
- Fixtures are checked in and regenerated deliberately; ids differ between runs, so never diff them against a previous version.
- A change to `EventApplier`, `FrameProjector` or `LogLines` regenerates the fixtures and ports the same change to `src/lib/live/` until `tests/agreement.test.ts` passes.
- A change to Godot's `CombatLog`, `RollEntry` or `UndoPlan` regenerates `tests/fixtures/combatlog.json` (`TABLETOP_WRITE_FIXTURES=1 dotnet test tests/Tabletop.Client.Tests --filter CombatLogViewerFixture`) and is ported to `src/lib/play/` until `combatLog.agreement.test.ts` passes. A change to any other ported core file is ported with its test.
- A new outbound message, or a new control that sends one, is not done until it has a case in `tests/fixtures/calls.json` (written from Godot's Core) and `calls.agreement.test.ts` passes. A difference is fixed in the browser, never in the fixture, unless the case shows a Godot bug, which is fixed in both with a test. The sends the pages build live in `.ts` modules (`lobbyEdits.ts`, `setup/edits.ts`, `handMove.ts`, `setup/drag.ts`, `gameOverView.ts`, `menus.ts`), so the replay calls what the pages call.
- `agreement.test.ts` replays the fixture events through the TypeScript `Applier` and `FrameProjector` and compares with the C# recording after `tests/normalise.ts`.
- `src/lib/live/` holds no rules: every name it prints is a string the event already carries.
- `VITE_API_BASE` (default empty, same-origin) sets the management base for the live feed; `VITE_GAME_SOCKET` sets the developer build's socket URL (the hosted build ignores it).
- The hosted build depends on the web app's storage key and shape (`tabletop.session`); a change there changes `src/lib/hosted/hosted.ts`.
- Node 24 via mise; `.npmrc` pins exact versions.
- Pages use the website's classes and tokens only (`docs/superpowers/specs/2026-10-25-play-ui-design.md` → Principles); check both themes. A page fits the window: side columns scroll inside themselves, the window never does. Show words, never ids or snake_case names.
